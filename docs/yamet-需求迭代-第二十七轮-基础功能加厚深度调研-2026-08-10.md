# 第二十七轮迭代需求：基础功能加厚 — 多视角深度调研

> 目标版本 **0.1.27**（功能性构建）。
> 用户命题：「基础功能加厚，深度调研，迭代需求」。含义：在前 25 轮将功能面铺到 46+ 工具、17 个 Rust 模块、26 个前端模块之后，对每条**用户日常高频触碰链路**做多视角系统性深度审计——不仅修 bug，更要识别"能跑但薄"的基础能力，在正确性、鲁棒性、安全性、体验完整性四个维度做实质性加厚。
> 调研方式：**五视角并行**（用户 / 后端 / 前端 / 安全 / 架构师），逐文件源码级审计。
> 调研规模：前端 ~15 个工具文件 + 6 个 lib 文件全读；后端 ~12 个模块文件全读/关键段读；安全 6 个函数级文件全读。

### 9.4 记忆语义检索

#### 现状审计

**score.rs（247 行）评分管线：**

```
query → tokenize（去停用词 + ≥3字符）→ 拉丁: substring match / CJK: 2-gram overlap
      → × time_decay（指数衰减）→ × source_weight
      → filter(min_score=0.05) → sort → MMR rerank(λ=0.7) → top-N
```

**核心局限：**
- 这是**精确子串匹配**（非 BM25、非 TF-IDF）——`"deploy" ≠ "shipping"`、`"性能优化" ≠ "提速方案"`
- 无 TF（词频）加权——出现 1 次和 10 次的词得分相同
- 无 IDF（逆文档频率）——高频词（如 "the"）与罕见词权重相同
- 无同义词/语义理解
- `recall_top` 全量 O(n) 线性扫描

#### 升级方案对比

| 方案 | 改进 | 新依赖 | 工作量 | 效果 |
|---|---|---|---|---|
| **A: TF-IDF 升级** | TF 加权 + IDF 统计 | 无 | 2 天 | 中（词频感知，仍无语义） |
| **B: BM25** | 标准信息检索算法 | 无 | 3 天 | 中高（业界标准，仍无语义） |
| **C: tantivy 倒排索引** | 真实全文检索引擎 | tantivy（~2MB 编译） | 5 天 | 高（BM25 + 字段 boost + fast） |
| **D: 本地 embedding** | 向量语义搜索 | ort + ONNX 模型（~200MB） | 15 天 | 极高（同义词+语义） |
| **E: 远程 embedding** | 向量语义搜索 | 无新 dep（已有 HTTP） | 5 天 | 极高（但需网络+API key） |

#### 推荐路径：渐进式

```
Phase 1（本轮 P3）：TF-IDF in score.rs（2 天，无新依赖，即时收益）
Phase 2（下轮）：    tantivy 倒排索引（5 天，真实 FTS 能力）
Phase 3（远期）：    本地/远程 embedding（取决于用户量和硬件基线）
```

**TF-IDF 实现要点（score.rs 改造）：**
1. 在 `recall_score` 中加入 `tf(line, token)` = token 在 line 中的出现次数 / line 总词数
2. 在 `recall_top` 前预计算 IDF：对所有 memory entries 统计每个 token 出现在多少 entries 中
3. final_score = `(tf × idf) × time_decay × source_weight`
4. CJK 部分保持 2-gram 但加入 TF 加权
