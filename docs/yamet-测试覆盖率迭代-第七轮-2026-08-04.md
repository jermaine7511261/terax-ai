## 三、下一轮补测建议（按投入产出排序）

### P1 高价值纯逻辑（无新依赖，vitest 原生 mock）

1. **`modelPrefs.ts`**（8.33%）— `toggleFavoriteModel`/`pushRecentModel` 纯函数，mock `LazyStore`。
2. **`planStore.ts`**（12%）— `newQueuedEditId` 格式。
3. **`customThemes.ts`**（14.28%）— 主题 JSON 解析纯函数。
4. **`themeFiles.ts`**（14.81%）— 主题文件名/内容解析。
5. **`context.ts`**（25%）— `resolvePath` 路径解析（安全边界）。
6. **`skills.ts`**（28.94%）— `parseSkillJson` 各种畸形输入。
7. **`pty-bridge.ts`**（2.63%）— 提取粘贴分块（32KiB）纯函数。
8. **`store/*`**（mcpStore/todoStore/snippetsStore）— 提取 reducer 纯函数，mock `LazyStore`。

> 预计：上述补测后全量语句可到 **35–38%**。

### P2 组件测试环境（需用户确认）

- 引入 `jsdom` + `@testing-library/react`
- 覆盖：设置页（SkillsMcpSection / AgentsSection / GeneralSection）、AI 面板（AiToolApproval / SnippetPicker / composer）
- 依赖增加与「始终轻量」主题冲突，**须确认后实施**。

### P3 低价值（不建议优先）

- `native.ts` / `keyring.ts` / `proxyFetch.ts`：纯透传封装，mock 成本高收益低。
- `TerminalPane` / `BlockOverlay` 等重型组件：测试基建投入大。
