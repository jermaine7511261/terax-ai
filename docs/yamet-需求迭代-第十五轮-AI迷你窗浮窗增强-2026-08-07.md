## 0. 本轮定位（用户命题）

用户聚焦「**AI 迷你窗（AiMiniWindow）**」——一个独立于全屏 AI 面板的浮层窗口。命题：**把这个功能好好构思迭代需求**，对照业界 AI 原生终端/编辑器的浮窗设计（Warp assistant、Claude Code/Codex 内联、VS Code Copilot Chat 浮窗、Ghostty 无边框 UI）找出差距并定稿成可执行需求。

**核心结论**（现状证据见 §2）：迷你窗**基础交互已非常扎实**（拖拽/8 向缩放/几何记忆/会话历史/上下文指示器/plan/todo），但存在真实缺口，其中一项是**主窗口产品缺陷**：
1. **【P0 用户命题】主窗口无 Todo**（`AiChatPanel` 无 Todo 渲染，todo 只在小窗 `AiMiniWindow:273` 可见——新用户建 todo 看不见）；
2. **Mini 窗无内嵌输入框**（`AiMiniWindow.tsx` Body 无 `AiComposerInput`，输入必须依赖全局状态栏 input bar，浮窗场景割裂）；
3. **会话切换丢输入草稿**（composer `value` 全局唯一，切会话不区分）；
4. **浮窗行为单一**（无边缘吸附/双击最大化/pin 置顶，对照现代浮窗工具落后）。

### P0 · 主窗口展示 Todo（T1/T2，用户命题，最高优先）
1. **主窗口挂载 TodoStrip**：`AiChatPanel`（ChatBody）渲染 `<TodoStrip sessionId={sessionId} />`，复用现有 `TodoStrip` 组件（自包含，只依赖 `todoStore` + sessionId）。
   - **方案 A**：TodoStrip 直接放主窗口会话底部（与迷你窗一致）。**（推荐，最小）**
   - **方案 B**：todo 非空时在会话顶部显示可折叠条（不占空间）。
   - **方案 C**：在主窗口消息流内联渲染（AI 用 todo_write 后紧跟 todo 卡片）。**（增强，需在 AiChat 消息渲染加 tool 分支）**
2. **位置**：主窗口 `AiChatPanel` ChatBody 容器底部（与迷你窗 `Body` 一致，`<div className="flex h-full ..."><AiChatView/><TodoStrip/></div>`）。
3. **迷你窗保留**：迷你窗 TodoStrip 不动（两处共享同一 store 数据，天然一致）。

**验收**：主窗口 AI 用 `todo_write` 建 todo 后，主窗口立即显示进度条 + todo 列表；迷你窗同步显示；`pnpm test` ai 模块绿。

### P0 · Mini 内嵌输入框（M1/M2）
1. **方案 A**：Mini Body 内嵌 `<AiComposerInput />`（复用全局 `AiComposerProvider` 实例，state 天然同步；全局 input bar 隐藏 Ai 输入时 Mini 仍可用）。
2. **方案 B**：Mini 内嵌独立 composer（新 provider 实例），与全局互不同步。**（不推荐，破坏一致性）**
3. **方案 C**：不内嵌，仅优化全局 input bar 在 Mini 打开时上浮。**（缓解不根治）**
> **推荐 A**：Mini 是独立浮窗，应自带输入；因 `AiComposerProvider` 顶层唯一，Mini 内嵌复用同一 provider 的 state（value/files/snippets 与全局共享），且需处理「全局 input bar 仍显示 Ai 输入」时的重复输入问题。

**验收**：Mini 打开时有输入框，可输入 + `/` 命令 + `@` 文件 + 语音；输入 state 与全局同步（在 Mini 打字、状态栏也显示）；`pnpm test` ai 模块绿。

### P0 · 会话切换保草稿（S1/S2）
1. **per-session 草稿**：composer `value` 改按 `activeSessionId` 分键存储（`useRef<Map<sessionId, string>>` 或 zustand）。
   - **方案 A**：composer 内 `useRef<Map>` 存每会话草稿，切换时读回。**（推荐，局部最小）**
   - **方案 B**：草稿进 `chatStore`（持久化到 localStorage，重启不丢）。**（增强，需持久化）**

**验收**：会话 A 输入半句 → 切 B → 切回 A 草稿保留；`composer.test.ts` 新增草稿用例。

## 4. 规划方案（技术设计）

### 4.0 主窗口 Todo（方案 A）
- `AiChatPanel` ChatBody 改为 `flex flex-col`：`<AiChatView/>` 占 flex-1，底部 `<TodoStrip sessionId={sessionId} />`（与迷你窗 `Body` 结构一致）。
- 复用 `TodoStrip`（自包含组件，零改动）；`sessionId` 从 ChatBody 现有 `sessionId` prop 传入。
- 数据天然一致：主窗 + 迷你窗都订阅 `useTodosStore.bySession[sessionId]`。

### 4.1 内嵌输入框（方案 A）
- `AiMiniWindow` Body 底部加 `<AiComposerInput />`（复用全局 provider state）。
- 需处理：全局 input bar 与 Mini 同时显示时，避免两个输入框抢焦点——Mini 打开时全局 input bar 的 Ai 输入隐藏（或 Mini 为唯一输入焦点）。
- 接缝：`WorkspaceInputBar` 的 `renderAi` 加条件 `!miniOpen`；Mini 显示输入框。

### 4.2 per-session 草稿（方案 A）
```ts
// composer.tsx
const drafts = useRef<Map<string, { value: string; files: FileAttachment[] }>>(new Map());
useEffect(() => {
  const key = sessionId;
  const prev = drafts.current.get(key);
  if (prev) { setValue(prev.value); /* files */ }
  else setValue("");
  return () => drafts.current.set(key, { value, files });
}, [sessionId]);
```
- 注意：切换时先保存当前会话草稿，再载入目标会话草稿。

### 4.3 边缘吸附（方案 A）
```ts
// miniWindowGeometry.ts
export const SNAP = 16;
export function snapGeom(g: Geom, vp: Viewport): Geom {
  // 距边 < SNAP → 吸附到 0 / vw-w 等
}
```
- 手势 `onUp` 时调用 `snapGeom`；`applyDrag` 保持原逻辑（拖动过程不吸附，松手吸附）。

### 4.4 置顶 pin（方案 A）
- `chatStore.ts` `MiniState` 加 `pinned: boolean`；`AiMiniWindow` 容器 className 按 pinned 切 `z-50`。

### 4.5 命令面板（方案 A）
- Mini 输入框 `onKeyDown` 检测 `/` 首字符 → 渲染 `SnippetPickerContent`（复用）显示 `SLASH_COMMANDS`。

## 6. 本轮不做（范围控制）

- **不做多显示器/DPI 感知**：`window.innerWidth` 单屏；多屏留后续轮。
- **不做 OS 级 always-on-top**（pin 方案 B 延迟）：本轮 pin 仅 z-index。
- **不做 Mini 独立持久化草稿**（P0-b 方案 B 延迟）：先会话内保活。
- **不重做几何引擎**：现有 11 测试的纯函数已良好，仅增量加吸附/最大化。
- **不改消息同步架构**：`chats` LRU + 共享 chat 实例已正确。
- **不做 E2E**。
