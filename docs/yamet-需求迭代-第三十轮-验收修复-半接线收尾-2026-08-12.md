## §1 关键发现（深度调研结论）

### 1.1 [P0] Provider 降级链：UI 完整、引擎空转 —— 本轮最高优先级

**证据链（递归 grep 全仓库）：**

- `resilience.rs` 定义了 CircuitBreaker / FallbackChain / RetryPolicy，但：
  - `chat_with_fallback` / `FallbackChain`：**0 处调用**（全 `.rs`）
  - `record_provider_failure` / `record_provider_success`：**0 调用方**（仅定义行）
  - `is_provider_available`：**0 调用方**
- TS 侧设置面板 `src/settings/sections/ProviderFallbackChain.tsx` **完整**：拖拽排序（setProviderFallbackChain 持久化）、断路器状态点（🟢/🔴/🟡）、4s 轮询 `resilienceStatus()`；已挂载进 ModelsSection。
- 但 `providerFallbackChain` 的全部消费方只有设置 UI 与偏好 store 自身——**chat 调用路径（runSubagent / lib/agent.ts buildConfiguredLanguageModel / 主对话）从不读取它**。

**结论**：断路器永远不会开合（无失败记录）、面板永远全绿、首选 provider 返回 429/5xx 时 agent 依旧直接中断。R29 P0-2 承诺的「自动 failover」**未兑现**，只是搭好了面板。

### 1.2 [P0] computer_read_tree 工具是空壳

- Rust `computer_read_accessibility_tree` **已实现**（Windows UIA `read_windows_uia_tree`，非 Win 返回明确错误）；`native.ts` 封装 `computerReadAccessibilityTree` 存在。
- 但 `tools/computer.ts` 的 `computer_read_tree.execute` **不调用它**，硬编码返回 `"accessibility tree is not implemented on this platform yet"`。
- 修复是一行接线，能力被白白晾着。

### 1.3 [P1] computer 工具双路径不一致 + click 丢参数

- 工具走**旧 session API**（`computerCapture` / `computerAction` id=0），而 R29 新增的 `computer/commands.rs`（computer_screenshot/click/type，原生支持 button）**无人调用** → 双实现漂移风险。
- `computer_click` 只发 `{kind:"click", x, y}`，**button 参数被丢弃**（schema 声明了 `left|right|middle`，payload 不带）。

### 1.4 [P0] 用户偏好建模：dead command

- `preferences.rs`：`preferences_extract` / `preferences_get` 两个 tauri 命令 + `native.ts` 封装齐全。
- 全仓库 **0 调用方**：无完成回调提取、无设置面板、无消费点 → R29 P1-2 子项未兑现。

### 1.5 [P1] i18n 缺口：9 个新工具无 key

- `translations.ts` 已覆盖 46 个旧工具名（R29 前 i18n 轮），但 9 个新工具（computer_screenshot/click/type/read_tree、model_fusion、generate_image、import_rules、lsp_hover、lsp_goto）**无双语 key**；computer.ts / fusion.ts / media.ts / importRules.ts / lsp.ts 的 description 硬编码英文。

### 1.6 [P1] 文档漂移

- `ROADMAP.md`「下一批」P0-1/2/3 与「更远期」P1-1/2、P2-1/2 仍全部 `[ ]` 未勾选（实际均已交付或部分交付，见 §0 表）。
- `docs/index.md` 迭代索引缺 29 轮条目（也缺 26 轮）。

### 1.7 外部调研结论（web 受限说明 + 本地实证）

- 沙箱网络：web_search / deep_search / fetch_url 均被 DNS 私有解析拦截（`host html.duckduckgo.com resolves to private/loopback`）→ 本轮外部调研不可行，**已如实记录**，不编造结论。
- 本地 E:\Agent 27 项目版本核对：flock 0.2.0、daedra 0.3.2、fetchira 0.1.13、terminator 0.24.32、computer-use-linux 0.4.6、claude-code-haha 999.0.0-local —— 与 08-11 对比报告**完全一致，无新版本可借鉴**。
- 结论：无新外部输入，本轮聚焦内部验收修复；web 深调研留待网络恢复后下一轮补。

### 1.8 附：model_fusion 小缺口

- R29 文档设想的 `web_search` 参数未实现（各模型无 web 工具面）；judge 未强制引用来源模型。

## §2 需求清单（本轮全部交付）

### 2.1 [P0] Provider 降级链真正接线（3 天）

**Rust 侧（1 天）**：`resilience.rs` 的 `record_provider_failure` / `record_provider_success` / `is_provider_available` 增加 `#[tauri::command]` 暴露给 TS（或收敛为 `resilience_report(kind, provider_id)` 单命令）。

**TS 侧（2 天）**：`lib/agent.ts` 新增 `callWithFallback`，作为所有模型调用的统一入口：

```ts
// lib/agent.ts
export async function callWithFallback<T>(opts: {
  modelId: string;
  keys: ProviderKeys;
  chain: string[];            // 来自 preferences providerFallbackChain
  attempt: (modelId: string) => Promise<T>;
}): Promise<T> {
  const order = dedupe([opts.modelId, ...opts.chain]);
  let lastErr: unknown;
  for (const id of order) {
    if (!(await native.resilienceAvailable(id))) continue; // breaker open → skip
    try {
      const r = await opts.attempt(id);
      void native.resilienceReport("success", id);
      return r;
    } catch (e) {
      lastErr = e;
      void native.resilienceReport("failure", id);
      if (isRateLimit(e)) await backoff(retryAfterMs(e));
      console.warn(`[resilience] fallback to provider ${id} after error: ${String(e)}`);
    }
  }
  throw new ChatError("AllProvidersFailed", lastErr); // 面板提示 / 回退 Ollama
}
```

**接线点**：`agents/runSubagent.ts` 的 generateText 调用 + 主对话模型调用（chatStore / useAiLiveBridge）统一走 `callWithFallback`；保留原 modelId 为首选。

**测试（1 天）**：单测（顺序 / 熔断跳过 / 退避计算）+ 集成（mock 429 → 切换 → 恢复日志断言）。
