# Yamet IM 与网关架构调研总结

> 调研日期：2026-08-03
> 调研对象：E:\Agent 下除 LangBot 外的 8 个候选项目
> 调研方式：并行子代理实际阅读各仓库源码（read_file / grep），非臆测
> 目标：回答「这些项目如何解决 IM（即时通信）与网关（gateway）问题」，为 yamet 设计 IM/网关能力提供可借鉴架构

## 0. 一句话结论

8 个项目中，**hermes-agent-main、claude-code-haha、grok-build-main、jiuwenswarm-openharmony 有实质的 IM/网关实现**；**opencode、oh-my-pi、terax、xora 无 IM 消息网关**（其"网关"指 agent 通信协议 / AI HTTP 代理 / 凭据代理等，非聊天消息投递）。对 yamet 最有价值的是 **hermes 的 relay 外连模式** 与 **grok/xora 的 ACP 协议层**。

| 项目 | 技术栈 | 有无 IM 网关 | 核心机制 | 一句话本质 |
|---|---|---|---|---|
| **hermes-agent-main** | Python | ✅ 20+ 平台 IM 网关 | `PlatformAdapter` trait + 注册表 + relay 外连 | 真正的多平台消息网关 |
| **claude-code-haha** | Bun/TS | ✅ 远程控制网关 | 长轮询 + CCR v2(SSE)，OAuth+JWT | 把本地 CLI 暴露给云端远程控制 |
| **grok-build-main** | Rust | ✅ Agent 通信网关 | ACP(NDJSON/JSON-RPC) + 独立 PTY WS | 传输无关的 agent 协议网关 |
| **jiuwenswarm-openharmony** | Python | ✅ Agent WS 网关 | WebSocket + E2A JSON，~200 方法 | 企业级 agent WebSocket 网关 |
| **opencode-dev** | Rust+TS | ❌（Slack 仅示例） | 对外 ACP + 进程内 SDK 事件流 | agent 核心 + 按需对外 server |
| **oh-my-pi-main** | Rust | ❌ | stdio RPC(JSONL) + TS 扩展 + 凭据代理 | 编码 agent + 扩展生态 |
| **terax-ai-main** | Tauri+Rust+React | ❌ | Rust 安全 AI HTTP 代理 + 子代理 + 钩子注入 | yamet 同源底座 |
| **xora-code-main** | Electron+Theia | ❌ | Theia JSON-RPC ⇄ ACP ⇄ Grok 侧车 | Grok 桌面 IDE |

## 1. 有 IM/网关的四个项目

### 1.1 hermes-agent-main —— 多平台 IM 消息网关（最值得借鉴）

**定位**：长期运行进程，统一连接 Telegram / Discord / Slack / WhatsApp / Signal / 飞书 / 微信 / QQ / Teams / Email / SMS / IRC 等 20+ 平台。

**统一流水线**（`gateway/run.py` 的 `GatewayRunner`）：
```
平台适配器收到原始事件 → 归一化 MessageEvent
  → BaseAdapter 活动会话守卫(入队+interrupt)
  → GatewayRunner._handle_message(): 认证 → 会话key → 斜杠命令? → 创建 AIAgent
  → SessionStore(SQLite 持久化) → delivery.py 按目标平台回发
```

**多平台抽象（关键）**：
- 各平台适配器（`plugins/platforms/<name>/adapter.py`）统一继承 `BasePlatformAdapter`，接口 `connect/disconnect/send_message/on_message`。
- `MessageEvent` 统一结构：`source(platform/chat_id/chat_type/user_id/thread_id/scope_id/profile)` + 归一化文本 + message_id。下游只看这个模型。
- **平台注册表 `platform_registry.py` + 延迟加载**：重 SDK（lark_oapi、discord.py、slack_bolt 等）只在真正用到时才 import，避免每次启动拖慢数秒。
- 传输随平台而异：Telegram 长轮询/webhook、Discord WS、Slack Socket-mode(WS)、WhatsApp webhook、Email IMAP/SMTP。**Webhook 型需公网入站端口；WS/Socket-mode/长轮询型由网关主动外连（无需公网端口）。**

**Relay Connector 模式（最高价值，见 2.1 详述）**：网关作为 WS 客户端 dial 出，无需公网入站端口。

**认证**：平台 token + 白名单 + DM 配对码 + 全局开关，默认拒绝。
**会话**：key 编码完整路由上下文 `agent:main:{platform}:{chat_type}:{chat_id}`，SQLite 持久化，PII 哈希脱敏，路径穿越防护。
**并发**：两级守卫（适配器层 + runner 层）+ `turn_lease` 单租约串行化 + 陈旧锁自愈。

### 1.2 claude-code-haha —— 远程控制桥接网关

**定位**：本机 bridge 进程作为"worker"，连回 Anthropic 云端 Environments API，把本地 `claude` CLI 暴露给 claude.ai 网页/桌面远程操控。本质是"任务分发/执行"网关，但其传输/认证/重连机制对任何 agent 网关通用。

**两条代码路径**：
1. **Environments API 长轮询**：`GET /work/poll` 拉工作项，`POST .../ack` 领取，`heartbeat` 续租（用 JWT 免 DB），`reconnect` 重新分派。容量控制：满载降为心跳保活 + 低频轮询，会话结束时 `capacityWake` 唤醒。
2. **CCR v2 直连**：SSE 读（`/worker/events/stream`）+ CCRClient 写（`POST /worker/events/{id}/delivery`），20s 心跳，`from_sequence_num` 续传。

**认证**：OAuth Bearer（管理操作）+ 会话 JWT（`sk-ant-si-`，心跳用 JWT 免 DB）+ 信任设备头。`createTokenRefreshScheduler` 解码 `exp`、过期前 5 分钟刷新、带 generation 防覆盖。

**重连**：指数退避（2s→120s→10min 放弃）+ 系统睡眠/唤醒检测。SSE 用 `Last-Event-ID`/`from_sequence_num` **续传而非回放全量**；epoch 不匹配(409)→ 回轮询环重新分派。

**消息**：回声去重（双有界 UUID 集）+ `control_request` 限时 ~10-14s 应答。

### 1.3 grok-build-main —— ACP Agent 协议网关（Rust）

**定位**：xAI Grok 的 Rust 实现。agent↔外部通信走 **ACP（Agent Client Protocol）标准协议**，封装成传输无关的信道网关（`xai-acp-lib/src/gateway.rs`）。

**传输/帧**：`\n` 分隔的 NDJSON，一行一条 JSON-RPC（`line_reader.rs`，64MiB 单行上限、cancel-safe）。

**两种接入**：进程内 GrokShell（`AcpClientChannel`，tokio mpsc 直接对接，无需 socket）+ Leader IPC 桥接（把 leader 原始 JSON 字符串信道适配成 typed ACP 信道，支持断线重连）。

**核心工程点**：
- `AcpGatewayReceiver`/`AcpGatewaySender` + `handle!` 宏把每条入站消息 spawn 任务；`AcpArgs` 携带 `oneshot::Sender` 关联请求/响应。
- **通知类消息一律 fire-and-forget**：注释明确——若阻塞等 ACK，在慢链路（IM/TCP 重传可达分钟级）会冻结整个流循环 → 会话挂死。
- **重连时持有陈旧消息 + 判定丢弃而非重放**（`same_channel` 判定）：重放陈旧 `session/load` 会在新连接触发二次全量 replay。
- `AgentShutdownGuard`：drop 时 cancel + join 工作线程，保证所有退出路径都发 `Shutdown`。

**PTY 独立通道**：`ptyctl` 用 axum 起 HTTP+WS 专门暴露终端控制（`/query/screen`、`/control/send`、`/wait` 长轮询、`/ws` 二进制流），与 ACP 控制协议物理分离。

### 1.4 jiuwenswarm-openharmony —— 企业级 Agent WebSocket 网关

**定位**：华为九问。单一 `AgentWebSocketServer`（约 7500 行）作 Gateway 与 AgentServer 之间的 WebSocket 服务端。

**协议**：私有 WebSocket + E2A JSON 协议。统一消息模型 `Message{type: req|res|event, channel_id, session_id, req_method, event_type, is_stream, stream_seq, stream_id, agent_ref}`。`ReqMethod` 枚举约 **200 个方法**（initialize、acp.tool_response、chat.send、session.*、command.*、permissions.*、**channel.feishu/slack/telegram/...**、skills.*）——**路由名即方法名**。

**IM 网关**：本身无"对外 IM 网关"概念，以 `channel.*` 方法开放多 IM 适配 + `gateway_push/` 服务端主动推送。

**流式/心跳（最完整）**：每条流式响应带递增 `sequence` + `is_complete`；空闲发 **keepalive chunk（sequence=-1）** 防 ping_timeout 掐断；`send_lock` 串行保证帧顺序；断开在 `finally` 依次取消所有 in-flight 任务 → cancel agent 内部工作 → 停调度器 → 清理流，避免孤儿任务。

## 2. 无 IM 网关的四个项目（各解决什么）

### 2.1 opencode-dev
对外主协议 **ACP**（`opencode acp`，完整实现 initialize/authenticate/newSession/loadSession/resumeSession/closeSession/forkSession/prompt/cancel）。核心为**进程内 SDK 事件流**（`stream.transport.ts` 订阅 `message.part.updated` 供 TUI 渲染）。可选 Web HTTP/WS server 供 Web UI / 外部 SDK / ACP client 连接。**IM 集成（Slack）是外部示例**：`@slack/bolt` + `createOpencode` 连 server，非核心内置。→ **"常驻进程内 + 按需对外 server" 的混合形态**是它最大的借鉴点。

### 2.2 oh-my-pi-main
无 IM 网关。唯一的"gateway"是 **Auth Gateway / Auth Broker**（`docs/auth-broker-gateway.md`）：LLM 供应商**凭据分发 HTTP 正向代理**，客户端永不见 access token（非消息网关）。agent 通信走 **stdio 上的换行分隔 JSON（JSONL RPC）**（`omp --mode rpc`，stdin 收 `RpcCommand`、stdout 发 `RpcResponse`/事件/扩展 UI 请求，启动发 `ready` 帧握手）。**扩展机制**：TS 模块导出默认工厂，接收 `ExtensionAPI`（`pi.on/registerTool/registerCommand/sendMessage`）。→ 借鉴其 **stdio RPC + TS 扩展面 + marketplace** 的"全开放"扩展模型。

### 2.3 terax-ai-main（yamet 同源底座）
无 IM 网关，但有**本项目已在用的"IPC 网关"** = Rust 侧**安全 AI HTTP 代理**（`src-tauri/src/modules/net.rs`）：
- `ai_http_request`(非流式) / `ai_http_stream`(流式，`tauri::ipc::Channel<AiStreamEvent>` 回调) / `lm_ping`(探活)。
- **SSRF 防护成熟度极高**：header 黑名单 + CRLF 注入拦截、`ip_kind()` IPv4/IPv6 分类（公网/私网/环回/云元数据）、`resolve_to_addrs` 把 reqwest 解析器钉在已分类 IP 上对抗 DNS rebinding、私网 opt-in、自定义重定向二次校验。
- 前端 `proxyFetch.ts` 把流式事件拼成 `fetch` 兼容 `ReadableStream`，让 Vercel AI SDK 透明消费。

外部 agent 集成：`agent.rs` 向 claude/codex/gemini/pi 的 `settings.json`/`hooks.json` **注入通知钩子 + OSC 777 终端标记**，前端解析标记显示 working/attention/finished 状态。

### 2.4 xora-code-main
无 IM 网关。**ACP 三明治架构**（最干净的 agent 前后端解耦范本）：
```
渲染进程(browser) ⇅ Theia JsonRpcConnectionHandler @ /services/xora-agent
electron-main: AgentHostManager → GrokAgentHostService
⇅ ACP(AcpClient，换行分隔 stdio JSON-RPC)
内置 Grok Build 侧车: `grok ... agent --no-leader stdio`
```
- RPC 契约：`agent-protocol.ts` 定义 `AgentHostService/AgentHostClient` + `RuntimePhase/ProviderProfile/AgentCapabilities`。
- 侧车生命周期：`GrokSidecarSupervisor` 负责 spawn、版本管理、**SHA-256 校验**、stderr 流式密钥脱敏、Windows `taskkill /T /F` 清理。

## 3. 跨项目提炼：10 条对 yamet 的核心借鉴点

按价值排序：

1. **主动外连 + relay/connector 模式**（hermes）—— 桌面 app 不开公网入站端口，作为 WS 客户端 dial 出，天然适配 NAT 后/移动端/网页远程控制。
2. **ACP 标准协议 + 传输无关信道层**（grok/xora）—— 协议语义与传输（stdio/WS/进程内）彻底解耦；yamet 可直接用 `agent-client-protocol` 生态，内部 mpsc + oneshot 关联请求/响应。
3. **一个 `PlatformAdapter` trait + 注册表 + 延迟加载**（hermes）—— 本地 Tauri IPC、Telegram、WhatsApp 都实现同一 trait，复用同一套会话/投递逻辑。
4. **双层凭证 + HMAC 签名 + 轮换窗口**（hermes/claude-code）—— 控制面/保活分离；WS 升级 token + 入站投递签名，多密钥列表支持轮换。
5. **指数退避重连 + 序号续传 + 陈旧消息丢弃**（grok/claude-code）—— 重连携带最后序号续传而非回放全量；`same_channel` 判定丢弃陈旧消息、由 re-init 显式重建，防二次副作用。
6. **fire-and-forget 处理无响应通知**（grok）—— 避免慢链路下冻结整个流循环。
7. **流式 = chunk + sequence + is_complete + 心跳**（jiuwenswarm）—— 空闲 keepalive chunk 防 ping-timeout；`send_lock` 串行保帧序。
8. **会话 key 编码路由 + 两级守卫 + turn_lease**（hermes）—— 单租约串行化轮次；陈旧锁自愈防卡死。
9. **PTY 独立通道**（grok ptyctl）—— 终端 I/O 与控制协议分离，REST 查询 + WS 二进制流 + 长轮询同步，便于权限隔离。
10. **常驻进程内 agent + 按需对外 server**（opencode）—— 默认进程内直连，仅需外部集成时再起 ACP/HTTP server。

## 4. yamet 现状对照

yamet 已具备 / 可复用：
- ✅ Rust 安全 AI HTTP 代理 `net.rs`（SSRF 全套，含 DNS rebinding 防护）—— 对应借鉴点 9 的 net 侧
- ✅ 外部 agent 启动器 + 钩子注入（`agent.rs`，OSC 777 生命周期标记）—— 对应借鉴点 2 的 agent 侧
- ✅ 进程内子代理 + 工具白名单（`agents/registry.ts`）
- ❌ 缺：统一 `PlatformAdapter` 抽象、relay 外连、真实 IM 平台接入、ACP 对外暴露、会话持久化 SQLite、多级守卫/租约
