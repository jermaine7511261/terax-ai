## 一、P0（高价值 · 功能不可用 / 能力脱节）

### A. AI 工具能力缺口（合并建议为一个功能构建 0.1.5）

**A1. Agent 无法直接驱动终端（`injectIntoActivePty` 已接线但无工具使用）**
- 【证据】`ai/tools/context.ts:13` 定义 `injectIntoActivePty`；`chatRuntime.ts:29`/`chatStore.ts`/`useAiLiveBridge.ts:94` 已接入；但 `tools/` 下**无任何工具调用它**。现有终端工具仅 `suggest_command`（terminal.ts:8-30，靠用户点击）、`get_terminal_output`（只读）、`open_preview`（仅 localhost）。
- 【现状】Agent 能读终端、能建议命令，但**无法在可见终端执行命令或向交互进程（REPL/dev server/npm prompt）打字**。
- 【缺口】"AI-native 终端"最大体验断点。**优先级最高，命中产品主线**。
- 【迭代建议】新增 `terminal_execute`（`injectIntoActivePty(text)` + 回车，`needsApproval:true`）与 `terminal_type`（注入不回车）；系统提示词（config.ts:499-530）补使用时机与"避免注入敏感凭据"约束。

**A2. 缺文件管理工具（delete / move / rename）**
- 【证据】`ai/tools/fs.ts:20-216` 仅 `read_file / list_directory / write_file / create_directory`。
- 【现状】Agent 删文件只能 `bash_run rm`（绕过 `checkWritableCanonical`，仅过 `checkShellCommand` denylist）。
- 【迭代建议】新增 `delete_file`、`move_file/rename_file`（`needsApproval:true` + `checkWritableCanonical` + plan mode 入队）。

**A3. 无 Git 工具（Rust 已备好全套 IPC）**
- 【证据】`tools/` 无 git 工具；`native.ts:271-393` 已封装 `gitStatus/gitDiff/gitCommit/gitPush/gitLog/gitListBranches` 完整 IPC。
- 【迭代建议】新增只读 `git_status`/`git_diff`（auto-exec）+ `git_stage`/`git_commit`（`needsApproval:true`）。

**A4. 图像附件无模型视觉能力门控**
- 【证据】`composer.tsx:295-304`/`360-383` 提交图像；`config.ts:131-143` `ModelTag` 含 `"vision"` 但 `MODELS` 仅 mistral 带标签（:184/192），默认 `deepseek-v4-flash` 无视觉；composer 全程未读 vision。
- 【迭代建议】发送前 `model.tags?.includes("vision")` 校验：不支持则 toast 拦截或自动切 vision 模型；附件透传子代理。

### B. 网关可用性缺口

**B1. 企微/公众号回调地址无法交付用户（开箱即不可用）**
- 【证据】`wecom.rs:196-203` 绑 `127.0.0.1:0` 随机端口，仅 `log::info!`；`official_account.rs:228-235` 同样；`GatewaySection.tsx` 无回调地址/复制/tunnel 引导 UI。
- 【现状】用户拿不到需填进平台后台的回调 URL，无内网穿透方案 → 两平台实际收不到消息。
- 【迭代建议】随机端口绑定后经事件回传前端，GatewaySection 显示"回调 URL + 复制按钮 + 隧道指南"；至少固定可预测端口。

**B2. 网关会话授权（白名单）不持久化，重启全部失效**
- 【证据】`session.rs:1-5` 注释说可持久化到 JSON，但 `approve/revoke/clear` 全是内存 `HashMap`，无磁盘读写；`commands.rs:57-74` 直接读内存。
- 【现状】已授权会话重启全退回 default-deny，用户需重新审批每个 chat。
- 【迭代建议】`SessionRouter` 白名单序列化到 app data，启动时随 `restore_from_keychain` 一并恢复。

**B3. 微信 iLink 会话过期后台 QR 重登是"静默失联"**
- 【证据】`weixin.rs:649-665` `poll_loop` 检测到 SessionExpired 直接 `qr_login()` 阻塞等扫码（截止 480s），QR 只发日志，前端无弹窗/通知。
- 【迭代建议】re-login QR 经事件推前端，系统通知/设置页弹"会话已过期请扫码"，确认后写回 keychain。

### C. 安全纵深缺口

**C1. Rust FS 层未强制工作区授权（单点防线）**
- 【证据】`fs/file.rs:128-158` `fs_write_file` 仅 `resolve_path` 后直接写，**从未调 `is_authorized`**；`workspace.rs:33` 的 `is_authorized` 现仅用于 spawn cwd。TS `security.ts` denylist 是 AI 写唯一自动化闸门。
- 【迭代建议】Rust `fs_write_file/fs_create_dir/fs_create_file` 加"解析后路径须处于已授权工作区"校验（复用 `WorkspaceRegistry::is_authorized`）；TS denylist 为第一道、Rust 为第二道。

**C2. `checkShellCommand` denylist 覆盖不全**
- 【证据】`security.ts:324-402` 拦 `rm -rf /`、`rm -rf ~/$HOME`，但不拦 `rm -rf .`/`rm -rf *`/`rm -rf 子目录`；`curl|bash` 不含 `sudo bash`；`dd of=/dev/sda` 不含 `> /dev/sda`；无 `chmod -R 777 /`、`shutdown`、`git push --force`。
- 【迭代建议】补齐高频破坏性模式；系统提示词传达 denylist 意图。

## 二、P1（重要 · 明显增益）

### 终端
**T1. 多行粘贴无确认，误执行命令风险**：`rendererPool.ts:285-294` Ctrl+Shift+V 直接 paste；`terminalPaste.ts:6-14` 无判断。→ 检测 `\n` 弹确认；复用 `useTerminalSession.ts:169-179` 的 bracketed-paste 包装（`\x1b[200~...\x1b[201~\r`）保证原子性。
**T2. macOS 普通终端 Cmd+C/V 未接线**：`rendererPool.ts:1043-1063` `isTerminalCopy/Paste` 均 `!IS_MAC`，Mac 恒 false；`TerminalPane.tsx:144-150` 裸 div。→ 按 `IS_MAC` 加 metaKey 分支 + Mac 右键菜单。
**T3. 普通终端无右键上下文菜单**：全库无 `onContextMenu`。→ 加复制/粘贴/全选/清屏/查找菜单。
**T4. 搜索状态不持久（`searchQuery` 从未赋值，死代码）**：`useTerminalSession.ts:464` init null、`:612` 传递、无赋值；`rendererPool.ts:502-506` 恢复逻辑成死代码。→ 搜索回调写回 `searchQuery` 或删除死代码。
**T5. `respawnSession` 与 in-flight `ptyOpening` 竞态**：`useTerminalSession.ts:759` 直接置 `ptyOpening=true` 无守卫，`attachSession:701` 有守卫。→ 并发互斥，复用同一 in-flight promise。

### 编辑器/LSP
**E1. 缺 quick-fix / code action**：`lsp/lib/client.ts:345-391` 仅 F12/Shift-F12/F2/格式化，无 `textDocument/codeAction`。→ 诊断 tooltip/lint 面板加"Quick fix"。
**E2. lint gutter 被隐藏**：`editor/lib/extensions.ts:56-58` `.cm-gutter-lint { width: 0px }`。→ 给固定宽度或移除规则。
**E3. 子代理只读，缺可写/执行子代理**：`agents/registry.ts:16-50` 全部 `READ_ONLY_TOOLS`。→ 新增 `code`/`executor` 子代理（edit/write_file/bash_run，仍需批准）。
**E4. 内联补全单候选、无 Tab 循环、上下文仅同目录**：`inlineExtension.ts:41-54` 单 `Suggestion`；`projectContext.ts:26-27` `MAX_SIBLINGS=4`。→ 多候选（`Alt-]`/`Tab` 循环）+ import 关系/最近编辑文件。

### Git
**G1. 完全无 stash**：`git/operations.rs`/`commands.rs`/source-control 全文无 stash。→ 新增 `git_stash_save/list/pop/apply/drop` + 面板"暂存改动"按钮 + 分支切换前提示自动 stash。
**G2. 无冲突解决能力**：`operations.rs:131-159` 未暴露 unmerged；全文无 merge/rebase；`git pull --ff-only` 遇分叉直接失败。→ 暴露 unmerged(`U`) + 冲突文件列表 + "保留我/保留远端/打开编辑器" + `merge --abort`。
**G3. push/pull/分支能力过窄**：`push`(:439-471) 无上游直接 `NoUpstream`；`pull_ff_only` 仅 `--ff-only`；无 create/delete/rename 分支。→ `--set-upstream`、`git_pull`(rebase/merge)、`git_branch_create/delete/rename`；**先把已存在的 `git_fetch`/`git_pull_ff_only` 接进 UI（source-control 从未调用）**。
**G4. 子模块完全未处理**：无 submodule 逻辑。→ status/fetch/pull 加 `--recurse-submodules`，识别 `.gitmodules`。

### 网关
**W1. QQ 适配器：access_token 从未使用 + 每次发送新建 WS + 默认端口算"已配置"**：`qq.rs:24-27` 定义未读；`run_onebot_loop`/`send_text` 不带鉴权头；`send_text`(:127) 每次 `connect_async`；`is_configured`(:84-86) 默认 `ws://127.0.0.1:6700` 恒非空。→ 握手带 `Authorization: Bearer` + 复用连接 + `is_configured` 校验 token + 返回真实 `message_id`。
**W2. 网关无入站限流/去重，审批丢消息内容**：`registry.rs:102-128` 逐条 `handler(ev)` 无限流无 `message_id` 去重；未授权会话只 `request_approval` 后丢原文。→ 令牌桶限流 + message_id 缓存去重 + `on_pending` 携带 sender+text 摘要。

## 三、P2（可选 · 打磨）

### 性能/健壮性
- **P2-1 快照序列化主线程同步执行**：`rendererPool.ts:626-643` serialize 5000 行在 `acquireSlot`(:407)/`reapIdleSlot`(:726) 临界路径同步跑。→ 非活动槽降上限（1000-2000）或挪 `requestIdleCallback`。
- **P2-2 BlockOverlay 签名判断前先做全部 DOM 读取**：`BlockOverlay.tsx:103-113` 先 `getVisible()`（`blockDecorations.ts:251-337` 每帧 `getBoundingClientRect()`+二分）后才比 `signature`。→ 轻量版本号/`lastViewportY` 短路。
- **P2-3 Windows `pty_has_foreground_job` 实际是"有无子进程"**：`mod.rs:234-237` Windows 分支返回 `shell_has_children`，后台任务也算"忙"。→ 注释对齐或接受保守行为。
- **P2-4 各适配器每次发送新建 reqwest::Client + 重复取 token**：`dingtalk.rs:404-441`/`feishu.rs`/`wecom.rs:145`/`official_account.rs:177`。→ 复用单一 Client + 缓存 token（仿 wecom.rs:44-78）。
- **P2-5 回调/签名比较非恒定时间，`constant_time_eq` 未被使用**：`crypto.rs:106-108` 短路比较；`wecom.rs:169`/`official_account.rs:105` 用 `==`。→ 真恒定时间比较。
- **P2-6 连接状态机无重复 connect 防护**：`registry.rs:82-131` 成功后 `connected.insert`，无"已在连接/已连接"拦截。→ per-platform idle/connecting/connected 状态机幂等。
- **P2-7 大粘贴单次大 IPC 写入**：`pty-bridge.ts:65` 一次编码整串。→ 前端分块写入。

### 编辑器/AI 打磨
- **P2-8 无 apply_patch/diff 编辑工具**：`edit.ts` 仅 `edit/multi_edit`。→ 增 unified diff 应用。
- **P2-9 项目记忆仅静态 YaMet.md，无会话内记忆累积**：`transport.ts:13-34` 只读根 YaMet.md。→ 记忆摘要写入记忆文件。
- **P2-10 modelCache 无清理 + compact 字节/4 粗估**：`agent.ts:72` Map 只增；`compact.ts:159` 粗估。→ LRU + 更准估算。
- **P2-11 补全无失败反馈**：`inlineExtension.ts:407-414` 失败静默。→ 首失败给一次性提示。
- **P2-12 补全不支持 `~`**：`pathComplete.ts:24` `if (dirPart.startsWith("~")) return null`。→ 用 `homeDir()` 展开。

### 文件/预览
- **P2-13 fs 把 UTF-16 文件误判为二进制（Windows 高频）**：`fs/file.rs:90-93` 仅靠前 8KB 含 NUL 判二进制。→ 先查 BOM（FF FE/FE FF）按 UTF-16 解码（复用 `workspace.rs:431-455` `decode_command_output`）。

- **P2-15 无真正的文件预览模块**：`tabs/lib/useTabs.ts:639-699` 只有 VS Code 式预览 tab，无 markdown/图片/PDF 内嵌渲染器。→ 加只读预览窗格。

### UX/文档/杂项
- **P2-16 状态栏信息密度低**：`StatusBar.tsx:49-82` 无 git 分支/ahead-behind（数据已在 `operations.rs:149-158`）。→ 状态栏加分支 + `↑N ↓M`；侧边栏加设置/主题/网关入口。
- **P2-17 主题导入撞 id 静默覆盖**：`validateTheme.ts:24` 校验严格；导入同 id 无提示。→ 冲突自动去重后缀/二次确认。
- **P2-18 `history_record` 不落盘**：`history/mod.rs:165-186` 只改内存。→ YaMet 自记录写盘。

### 发布/依赖/SSRF 专项（本调研交叉验证独有确认）
- **P2-23 `@ai-sdk/{openai,anthropic,google,groq,xai,cerebras}` 是死依赖（bundle 白占）**：`package.json` 声明 6 个，但 `src/` 全 0 引用（连 deepseek/mistral/openrouter 也 0）——`config.ts` 仅 5 provider 且全走 `@ai-sdk/openai-compatible`。→ `pnpm knip` 清理；README/YaMet.md provider 章节改为现实表（5 + 具名 custom endpoints + llama.cpp）；`DEFAULT_MODEL_ID` 与 MODELS 对齐。
- **P2-24 自动更新不可用（`endpoints: []`）**：`tauri.conf.json:109` updater 无发布源（pubkey 在，签名链就绪但 fork 未接自己的 latest.json/Release）。→ 接通发布流水线（tag→build→sign→upload→latest.json）；README 安装节不再指向 "your-org"。
- **P2-25 `::ffff:` IPv4-mapped IPv6 绕过 SSRF 阻断**：`net.rs` `ip_kind` 的 V6 分支（:55-73）不解包 mapped 地址，`::ffff:169.254.169.254`/`::ffff:127.0.0.1` 会被当 Public/Loopback 误判——`Ipv6Addr::is_loopback` 对 mapped 返回 false，link-local 元数据可被绕过。→ `ip_kind` V6 分支先 `to_ipv4_mapped()` 解包再走 V4 分类，补单测钉死该边界。
- **P2-26 WebView2 引导配置与 README 矛盾**：`tauri.conf.json:72` 实为 `downloadBootstrapper`，README 声称 embed 离线。→ 对齐文档或改配置。
