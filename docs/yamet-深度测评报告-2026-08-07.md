- **前端平台抽象层**（`@/platform`）是亮点：136 个 API 统一封装 invoke/Channel/convertFileSrc/store 等，web/tauri 双实现，是 Web 化/测试化的关键。

## 四、后端深度评审

### 4.1 强项（逐条核实）

1. **`net.rs` — SSRF 纵深防护（本工程最佳代码之一）**
   - `ip_kind()` 正确处理 IPv4-mapped IPv6（`::ffff:169.254.169.254` 不会被误判为公网）、AWS `fd00:ec2::254`、link-local、CGNAT；
   - `classify_and_collect_safe_ips` + `reqwest::Client::resolve_to_addrs` **IP 钉扎**，从根上防 DNS 重绑定；
   - 重定向策略逐跳重新做 scheme/host/userinfo/metadata/私网分类；
   - header 黑名单（hop-by-hop）+ CRLF/NUL 注入拒绝；响应体 64 MiB 硬上限；流式通道被前端 drop 即中止。
   - 自带 10+ 单元测试覆盖上述分类。

2. **`fs/policy.rs` + `workspace.rs` — AI 读写双闸门**
   - 前端 `security.ts` 与后端 `policy.rs` 规则逐条镜像（.env/私钥/受保护目录/系统写前缀/ADS/尾点空格/大小写归一），后端为权威闸门；
   - `checkReadableCanonical` 先查字面路径再查 canonical 路径，防 symlink 穿越；`workspace::is_authorized` 用 `Path::starts_with` 前缀匹配 canonical root；
   - AI 写路径强制 workspace 授权 + 秘密清单，实测有对应 Rust 与 TS 测试。

3. **`secrets.rs` — 平台密钥存储**：macOS/Windows 走 keyring；Linux 明文 JSON 但有 0600 + 原子 rename + `sync_all` + 并发写锁（`with_store_mut` 持锁写完），并有"写盘后无 tmp 残留/覆盖原子性"等测试。

4. **`git/` — 命令构造安全**：全部数组参数 + `--` 分隔 + `-z` 解析；分支名校验（拒绝前导 `-`/空白/控制符）；stash 索引从 `git stash list` 输出回取；`remote_url` 校验 remote 名字符集。

5. **`pty_helper/` — 会话恢复协议**：loopback + 随机端口 + token 首帧鉴权 + 1 MiB 帧上限 + 10 分钟孤儿超时 + 退出时显式 shutdown，token 文件 Unix 0600。

6. **`proc/job.rs`**：Job Object + `KILL_ON_JOB_CLOSE`，drop 即整树回收，带真实子进程测试。

7. **`main.rs`/`lib.rs` 生命周期**：Exit 事件显式 kill 全部 LSP/MCP/DAP 子进程 + 通知 helper 退出；macOS `Opened` 事件单独处理文件去重。

### 4.2 发现的问题

**[SHOULD] `src-tauri/src/modules/shell/mod.rs:341-350` — Windows 超时路径进程树回收有窗口期**
超时分支里 `ProcessJob::create_for(child.id())` 是在 `recv_timeout` 返回超时**之后**才创建 Job 并挂接的。等待期间 shell 已派生的孙进程（如 `pnpm dev` 的子进程）不在 Job 内，超时 kill 只杀掉 shell 本身，孙进程可能逃逸。Unix 侧用 `process_group(0)` 从 spawn 起就成立，无此问题。
→ 建议：spawn 成功后立即 `create_for` 并持有到进程结束（`kill_reaps_process_tree_via_job_object` 测试已证明 drop 语义，只是调用时机不对）。

**[SHOULD] `src-tauri/src/modules/net.rs:499-560` — `ai_http_stream` 无整体读超时**
`req.send().await` 与 `bytes_stream()` 循环都没有 `tokio::time::timeout` 包裹（`ai_http_request` 有 60s/120s 超时，流式版没有）。服务器 accept 后不发数据可长期挂住连接（泄漏 fd/内存）。
→ 建议：给 send 加超时，并对"两个 chunk 间隔"加读空闲超时（流式场景不宜用整体时长）。

**[SHOULD] `src-tauri/src/modules/git/operations.rs:1247-1272` — `push_upstream` 的 remote 参数未校验**
`remote.unwrap_or("origin")` 直接进入 `["push", "--set-upstream", &remote_name, &branch]`。恶意/失误的 remote（如 `--delete`）可被 git 当选项解析（`git push --set-upstream --delete <branch>` 会删远端分支）。前端当前不传该参数，风险低，但 `remote_url()` 已有 `is_remote_name_char` 校验，此处应复用。
→ 建议：对 remote 用同一字符集校验，拒绝空/超长/非法字符。

**[NIT] `src-tauri/src/modules/fs/policy.rs:139-144` — 每次匹配都编译正则**
`secret_basename_match` 对每个 basename 循环 `regex::Regex::new(re)`。AI 写路径高频调用时是无谓开销。
→ 建议：`static`/`OnceLock` 预编译。

**[NIT] `tauri.conf.json` — `assetProtocol.scope: ["**"]` 全开放**
asset:// 协议 scope 放开到任意路径。配合 CSP 的 `img-src/media-src/frame-src asset:`，理论上 webview 内任意 XSS 可用 asset:// 读取本机文件（受 CSP base-uri/self 限制，且当前无注入点，故为 NIT）。
→ 建议：按实际用途（预览/主题/图片）收紧到工作区与资源目录。

**[NIT] `src-tauri/src/modules/proc/job.rs`** — `AssignProcessToJobObject` 在目标进程已属其他 Job（不允许嵌套）时静默失败，仅返回 Err 后 kill 单进程；可接受，但注释里可说明嵌套 Job 依赖（Win8+）。

## 五、前端深度评审

### 5.1 强项

1. **无 XSS 注入点**：全 src（634 文件）grep `dangerouslySetInnerHTML` 为 0；AI 聊天用组件化渲染（`RenderedMessage`/`RenderedPart` + streamdown 流式解析），markdown 不落 HTML。
2. **AI 工具层安全护栏**：`tools/fs.ts`、`edit.ts`、`search.ts`、`createSkill.ts` 全走 `checkReadableCanonical`/`checkWritableCanonical`（含 symlink 二次校验）；`shell.ts` 走 `checkShellCommand` + `needsApproval`；会话级 shell 缓存带失败重试（`sessionShells`）。
3. **平台抽象层**：`@/platform` 统一封装，`native.test.ts` 锁契约；gateway/dap/mcp 均有类型化 `api.ts`（snake_case 契约测试防漂移）。
4. **性能工程**：manualChunks 精细拆分（xterm/codemirror/streamdown/各 AI provider 独立 chunk）、eager 预算（540KB）、`@tanstack/react-virtual` 虚拟列表、React Compiler preset + `react-compiler-healthcheck`（CI advisory）。
5. **测试纪律**：171 个测试文件与实现同构（每个 lib 都有对应 .test），`AiToolApproval`、`useTabCloseGuards`、`PreviewPane`（锁定 iframe sandbox 属性的源码级回归测试）等关键 UI 逻辑都有覆盖。

### 5.2 发现的问题

**[SHOULD] 前端覆盖率绝对值偏低（31.9% stmts），settings 层全空**
coverage 报告显示 `settings/sections/` 下 ModelsSection(96-1455 行)、ProvidersSection、AccountsSection、ToolsSection(96-1455)、NotificationsSection 等**全部 0%**；`ai/components/` 大量组件 0%。UI 组件大而空是当前最大测试缺口。
→ 建议：优先给 settings 核心逻辑（模型配置持久化、provider 增删、密钥校验路径）抽 lib 层补单测，再补少数关键交互。

**[NIT] `src/app/App.tsx`（1524 行）、`src/modules/source-control/SourceControlPanel.tsx`（1686 行）、`useSourceControlPanel.ts`（1167 行）超长**
已有拆分先例（`SourceControlBits.tsx`），建议继续按渲染/逻辑分片；React Compiler 下大组件 re-render 成本也可借此收敛。

**[NIT] `src/modules/preview/PreviewPane.tsx:214` — iframe `allow-same-origin` + `allow-scripts` 组合**
该组合理论上允许 iframe 自解除沙箱；但预览内容是用户自己的 dev server（需同源做 HMR），外部 URL 走原生子 webview（README 已说明），属有意取舍。已有测试锁定属性防回归，保留。

**[NIT] i18n**：仅 zh/en 双语（`AssertSameKeys` 守卫已恢复，硬编码英文清零），覆盖广但语种少——对"产品成熟度/中文为主"定位足够，国际化则不够。

## 七、风险清单（按优先级）

1. **[中] 发布链路未落地**：updater 端点/README 仓库名全是占位符——`{owner}/{repo}` 意味着即使发布，自动更新也指向错误地址。发布前必须替换并配好 pubkey/签名（pubkey 已有真实值，说明半只脚已踏入发布，端点却未同步）。
2. **[中] Windows 超时 kill 的进程树逃逸窗口**（见 4.2 #1）：影响 `shell_run_command` 超时与 `bash_background` 类操作的资源回收。
3. **[低] `ai_http_stream` 无读超时**：本地/远端模型服务异常时可挂住连接。
4. **[低] 前端覆盖率绝对值低**：不影响当前门禁（阈值已适配），但 31.9% 对"测试工程化"卖点而言是短板；settings 层 0% 是下次迭代最划算的补点。
5. **[低] 仓库卫生**：19 个一次性脚本入库会让新贡献者困惑；建议移入 `scripts/archive/` 或删除。
