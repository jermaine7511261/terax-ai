# Yamet 参考项目调研与迭代需求（2026-08-04）

> 背景：`E:\Agent` 下收集了 9 个优秀 AI 项目。用户要求「迭代需求参考这些优秀思路」。本调研逐项目读 README/架构（顶部源码直读），提炼对 Yamet 可借鉴的能力，转成迭代需求。第六轮（MCP client / Skill 升级 / 记忆增强）已定方向，本调研给出佐证与强化，并产出第七轮候选。

## 二、优秀思路提炼（按借鉴价值）

### H 系列 · Hermes（价值最高）

- **H1 会话语义检索**：FTS5 全量会话搜索 + LLM 摘要，实现跨会话回忆（"search its own past conversations"）。Yamet 已有会话历史列表（第五轮 U1），但无跨会话语义召回。
- **H2 skills 自改进 + 主动记忆 nudge**：agent 完成任务后自动创建 skill，使用中自我改进；周期提示把知识写入持久记忆（periodic nudges）。Yamet 的记忆是工具驱动（update_project_memory），无自动沉淀与 nudge。
- **H3 cron 定时自动化**：内置调度器，自然语言定义每日报告/夜间备份/每周审计，投递到任意平台。Yamet 无调度能力。
- **H4 多执行后端**：local / Docker / SSH / Singularity / Modal / Daytona，serverless 空闲休眠按需唤醒。Yamet 已有 SSH 终端 + WSL 工作区，可扩展「命令执行目标」（bash_run 指定容器/远程）。
- **H5 委托并行 + RPC 工具调用**：子 agent 并行工作流；脚本经 RPC 调工具，多步管道零上下文成本。Yamet 已有 run_subagent（顺序委托），无并行工作流与 RPC。

### L 系列 · LangBot

- **L1 平台自身即 MCP server**：`/mcp` 暴露精选服务层给外部 agent。Yamet 第六轮做 MCP client（接外部工具）；反向做 MCP server（把终端/文件/git 能力暴露给 Claude Code 等）是天然互补，外部 agent 编排 + 自有能力对外。
- **L2 RAG + vector DB**：项目知识库问答。Yamet 无向量检索。
- **L3 Plugin/Box 沙箱运行时**：隔离的执行运行时（langbot-plugin-sdk 的 Box Runtime）。Yamet 插件系统 out of scope，但「安全命令沙箱」（Docker/Box 隔离的 bash）与 H4 呼应。
- **L4 skills/ 目录单一事实来源**：仓库内 skills 目录 + 元数据激活。与第六轮 Skill 升级一致，可补充「内置 skills 目录 + 规范文件」。
- **L5 web 管理面板**：Yamet 是桌面形态，列为可选。

### X 系列 · Grok Build / Xora Code（ACP）

- **X1 ACP 集成**：Agent Client Protocol 是标准 agent 嵌入协议（流式消息、计划、工具调用、权限请求、会话事件）。Yamet 对外部 agent 用 CLI print-mode + OSC 133 检测；ACP 是更深的嵌入形态（sidecar 托管、权限请求结构化）。列为远期。
- **X2 Skills/MCP 统一配置入口**：一处配置 skills 与 MCP。呼应第六轮设置页。
- **X3 凭据/权限裁决不放渲染页面**：Yamet 已是该模型（Rust 持 OS 访问 + IPC 白名单），验证方向正确。

### O 系列 · oh-my-pi

- **O1 DAP 调试操作**（28 个 ops）：agent 驱动断点/单步/变量查看。Yamet ROADMAP 明示集成调试器 out of scope。本调研佐证该能力有真实价值，但工程量大；建议维持 out of scope，列为远期方向性讨论。
- **O2 大工具面 + LSP ops**：32 工具 + 14 LSP ops。Yamet LSP 已有（F12/引用/重命名/格式化/诊断），不追平数量，按需补齐。

### C 系列 · claude-code-haha（Claude Code 架构）

- **C1 Recovery CLI 降级模式**：主路径异常时降级恢复 CLI。Yamet 无显式降级模式，列为打磨项。
- **C2 MCP + 插件 + Skills 三系统齐备**：验证第六轮「MCP client + Skill 升级」方向正确，Claude Code 生态已标准化。
- **C3 权限安全设计**（工具系统/服务层/状态数据流分层）：与 Yamet security.ts + 审批流同构，方向一致。

### T 系列 · Terax（同源上游）

- **T1 版本差**：Terax v0.8.6 vs Yamet v0.1.6，上游迭代更久。**建议：diff 上游功能增量**（模块/依赖/UI），吸收 Yamet 缺的上游改进；Yamet 独有（IM 网关、SSH、spaces、block 终端、agent 编排）不回退。
- **T2 provider 包策略差异**：Terax 保留 6 个 `@ai-sdk/*` provider 包，Yamet 删除统一走 `@ai-sdk/openai-compatible`（包体积优化，有意为之，不回退）。

## 三、迭代需求（按优先级）

### 佐证并强化第六轮（已定方向）

| 项 | 强化点 | 参考 |
|---|---|---|
| 第六轮 P1 MCP client | 设置页做成「Skills/MCP 统一配置」入口（X2）；MCP 工具卡可含 server 来源（已有方案） | LangBot / Xora / Claude Code |
| 第六轮 P2 Skill 升级 | 增加「内置 skills 目录」约定（`skills/` 单文件规范，L4）；验收对齐 agentskills.io 类开放标准的可行性评估（H2） | Hermes / LangBot |
| 第六轮 P2 记忆增强 | 记忆浏览 UI 之外补「主动 nudge」：任务结束或会话收尾时，agent 经工具提示把值得沉淀的知识写入记忆（H2）；条目按来源分组（自动沉淀 vs 手动） | Hermes |

### 第七轮候选（新，按优先级）

| 优先级 | 项 | 方案要点 | 参考 |
|---|---|---|---|
| **P1** | 反向 MCP server：Yamet 能力对外暴露 | 新增 `mcp_server`（stdio/SSE 监听）：把既有命令（终端上下文、文件、git、搜索）按 MCP 工具 schema 暴露；外部 agent（Claude Code 等）可经 `mcpServers` 配置接入；复用现有授权/审批语义（只读默认、写需客户端侧同意） | LangBot L1 |
| **P1** | 跨会话语义检索 | 后端历史记录索引（复用 `~/.yamet/history` 与会话存储），FTS 或 SQLite 全文索引；agent 工具 `search_memories(query)` 检索历史会话 + 相关记忆条目，结果摘要注入上下文 | Hermes H1 |
| **P2** | cron 定时自动化 | 后端调度器（tokio interval + cron 解析），任务定义（自然语言 prompt + 调度表达式 + 投递目标：通知/IM/新会话）存 preferences；到点 spawn agent 任务，结果投递 | Hermes H3 |
| **P2** | 命令执行目标扩展 | `bash_run`/`shell_session` 支持可选 `target`（local / docker exec / ssh host），复用既有命令守卫 + 授权；先做 Docker（`docker exec` 校验镜像/参数） | Hermes H4 |
| **P2** | skills 自动沉淀 | 长任务完成后 agent 可选调用 `create_skill(name, prompt, toolAllowlist)` 沉淀可复用技能（走审批）；skills 列表在设置页可启停 | Hermes H2 |
| **P3** | Recovery 降级模式 | 主渲染路径启动失败或关键命令反复失败时，提供最小可用 fallback UI/命令入口与日志导出 | claude-code C1 |
| **远期** | ACP 外部 agent 深度嵌入 | 评估 ACP（Rust client crate）替代/补充 CLI print-mode 编排：结构化流式消息、计划、权限请求 | Grok/Xora X1 |
| **远期** | DAP 调试 | 与 ROADMAP out of scope 冲突，仅记录方向性参考，不在近期排期 | oh-my-pi O1 |

### 方向决策

- **Terax 上游对比**：抽一个独立小任务，diff `E:\Agent\terax-ai-main` 与 Yamet 的功能增量（模块列表、依赖、UI 组件），产出吸收清单；Yamet 独有能力不回退。建议排在第七轮调研项。
- **DAP / 集成调试器**：维持 ROADMAP out of scope（轻量定位），oh-my-pi 的能力仅作长期信号。
- **插件系统**：维持 out of scope（第六轮已定）；L3 沙箱运行时并入「命令执行目标」而非独立插件体系。
