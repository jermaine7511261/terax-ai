# 第十九轮迭代需求：模型/智能体分离 + 模型持久化 + 上下文用量展示 + 思考长度

> 目标版本 **0.1.20**（功能性构建）。基于 v0.1.19（已含深度测评 P1 全部修复 + 工作区授权修复 + 发布链路/安全/卫生审查修复）。
> 用户原话需求：
> 1. 「前端模型与智能体是合并的，需分开」
> 2. 「模型每次启动需重新选择模型，没有持久化」
> 3. 「模型应该从官方拉取到模型上下文大小，像 Hermes 一样在底部状态栏显示已用百分多少」
> 4. 「底部模型选项应该有模型思考长度选项卡，参考 Hermes 的」

---

## 0. 本轮定位

**状态栏 AI 模型/智能体体验重构**。把当前合并的 `AgentSwitcher`（一个下拉里 agent+model 两个区块）拆成两个独立选择器，并补齐模型选择的持久化、上下文用量百分比展示、思考长度选项卡。全部改动集中在 `src/modules/ai/`（components / config / store / lib）+ `src/modules/settings/`（持久化）+ 状态栏渲染。

> **覆盖旧规则**：此前 skill 参考 `ai-statusbar-selector-layout.md` 要求 agent+model **合并**在状态栏一个下拉。用户本轮明确要求「分开」，故拆成两个并列选择器，仍只渲染在状态栏（`AiStatusBarControls`），不进入 AiMiniWindow/AiChatPanel。

## 1. 基线调研（真实代码）

### 1.1 现状：合并的选择器
- `AgentSwitcher`（`src/modules/ai/components/AgentSwitcher.tsx`）：单个 `DropdownMenu`，内含 agent 区块 + `ModelSection` 区块。触发器显示 `agent名 · 模型名`。
- 渲染点唯一：`AiStatusBarControls.tsx:50`（状态栏）。AiMiniWindow/AiChatPanel 无。
- `ModelSection` 已有搜索、隐藏无 key 模型、favorite/recent 提示等逻辑——可复用拆出。

### 1.2 现状：模型选择不持久化
- `chatStore.selectedModelId`（chatStore.ts:181/330）初始 `DEFAULT_MODEL_ID`，`setSelectedModelId`（331-334）只 `set` + `pushRecentModel`，**不持久化** → 每次启动回到 DEFAULT。
- 持久化基础设施已有：`preferences.ts`（`favoriteModelIds`/`recentModelIds`）+ `settings/store.ts`（`setFavoriteModelIds`/`setRecentModelIds`，KEY_FAVORITE_MODELS/KEY_RECENT_MODELS）。**缺的是"当前选中模型"的持久化字段**。

### 1.3 现状：上下文大小已有数据源（未接 UI）
- `MODEL_CONTEXT_LIMITS`（config.ts:317）已导出：各模型上下文上限（deepseek-v4-pro/flash=1M、deepseek-reasoner=128K 等）。辅助 `getContextLimit(modelId)`（config.ts:373，默认 128K）。
- `fetchProviderModels`（providerModels.ts:35-76）能从官方 `/models` 端点拉取 `contextLength`（`context_length`/`contextLength` 字段）——需求3"从官方拉取"所需。已有 store `useFetchedModelsStore` 缓存。

### 1.4 现状：已用 token 统计
- `agentMeta.tokens.inputTokens`（chatStore.ts:57/75，chatRuntime.ts:89-100 累加）——当前会话累计输入 token。这是"已用"的准确来源。
- **无** `outputTokens` 累加进同一统计的持久展示（tokens 结构含 input/output/cached，但状态栏未展示）。

### 1.5 现状：思考长度无配置
- agent 调用有 `reasoning: keepsReasoning ? "none" : "before-last-message"`（agent.ts:376）——推理保留策略，非"思考长度"。
- **无** `reasoning_effort`/thinking budget 的模型级配置与持久化。

## 2. 需求项

### P0-1【核心】模型与智能体分开（两个独立选择器）
**现状**：`AgentSwitcher` 合并 agent+model。
**目标**：拆成 `AgentSwitcher`（纯智能体）+ `ModelSwitcher`（纯模型），并排在 `AiStatusBarControls` 状态栏，各自独立下拉。
- `ModelSwitcher`：触发器显示模型名 + 模型图标；下拉复用现有 `ModelSection` 逻辑（搜索 / 隐藏无key / favorite/recent / 无key跳设置）。
- `AgentSwitcher`：触发器只显示 agent 名 + agent 图标；下拉保留 agent 列表 + "Manage agents…"。
- 两选择器仍**只渲染在状态栏**（`AiStatusBarControls`），不进 AiMiniWindow/AiChatPanel。
- 移除 `AgentSwitcher` 中触发器里的 `· 模型名` 部分。
**验收**：状态栏显示两个独立按钮（agent 一个、model 一个）；`grep AgentSwitcher src/modules/ai/components/` 只有 AgentSwitcher.tsx 定义 + AiStatusBarControls 引用；`grep ModelSwitcher` 只在 ModelSwitcher.tsx + AiStatusBarControls；tsc + vitest 绿。

### P0-2【核心】模型选择持久化
**现状**：`selectedModelId` 不持久化，重启回到 DEFAULT。
**目标**：新增持久化字段 `selectedModelId`，`setSelectedModelId` 时写入 preferences，启动时读取恢复。
- `settings/store.ts`：新增 `KEY_SELECTED_MODEL = "selectedModelId"`，DEFAULT `selectedModelId: null`（null=用 DEFAULT_MODEL_ID），加 `getSelectedModelId`/`setSelectedModelId`。
- `preferences.ts`：加 `selectedModelId: string | null` 字段。
- `chatStore`：`setSelectedModelId` 调持久化；启动/初始化时若持久化值存在则用它覆盖 DEFAULT。
- 与现有 `favoriteModelIds`/`recentModelIds` 并存。
**验收**：选择模型 → 重启 → 恢复该模型；`modelPrefs.test`/`store.test` 补测；tsc 绿。

### P0-3【核心】状态栏显示上下文已用百分比（与压缩触发同源）
**现状**：压缩逻辑已存在（`compactModelMessagesDetailed`）且**已用百分比判断**——`approxBytes(messages)/4` ≥ `0.55*contextLimit` 删被覆盖 read、≥`0.7*contextLimit` 进一步 elide、目标回落 `0.6*contextLimit`。但状态栏无展示。
**目标（用户修正）**：状态栏显示的"已用上下文百分比"必须是**判断压缩的依据**——即与 `compactModelMessagesDetailed` 用同一数据源（`approxBytes(当前会话 messages)/4` ÷ `getModelContextLimit`），让用户看到的百分比精确等于"距压缩触发还有多远"。不是独立的装饰性统计。
- 数据源：`approxBytes(getChat().messages)/4`（与压缩同源的近似 token）+ `getModelContextLimit(selectedModelId, compatOverride)`（与压缩同源的上限）。
- UI：`ModelSwitcher` 触发器旁紧凑百分比/进度条，实时更新；接近 55%/70% 阈值时变色警示。
**验收**：状态栏百分比与压缩触发逻辑同源（同一近似 token 计算）；agent 运行中数值增长；无消息时 0%；tsc 绿。

### P0-4【核心】模型思考长度选项卡（参考 Hermes）
**现状**：无思考长度配置。
**目标**：`ModelSwitcher` 下拉加"思考长度"选项卡，可选（如 off/低/中/高 或 Hermes 式数值档位），持久化。
- 新增持久化字段 `thinkingLength`（枚举：`off | low | medium | high`，或数值）。
- 作用于 agent 请求的 `reasoning_effort`/thinking 参数（接 agent.ts:376 的 reasoning 配置链）。
- 放 `ModelSwitcher` 下拉内一个独立区块（"思考长度" + 几个档位），或在触发器旁一个二级菜单。
**验收**：模型下拉可选思考长度；选择持久化；agent 请求带上对应参数；tsc 绿。
