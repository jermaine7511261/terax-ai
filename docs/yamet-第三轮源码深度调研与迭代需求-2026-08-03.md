## 一、总体架构与规模

- 两进程模型：Rust（`src-tauri/`，58 个 `.rs` 文件）持有全部 OS 访问；webview 只经 `invoke()`。`lib.rs` 的 `invoke_handler` 注册 **94 个命令**（pty 11、fs 20、git 22、shell 9、lsp 5、workspace 4、net 3、secrets 4、gateway 9、history 4、agent 2、misc 3）。
- 前端：React 19 + TS，`src/` 下约 400 个 `ts/tsx`，按 `modules/<area>/` 自包含组织，i18n 双语（zh 主 / en 回退）。
- 版本一致性：`0.1.4` 在 package.json / Cargo.toml:3 / tauri.conf.json:4 三处一致。`identifier: app.yamet.yamet`（tauri.conf.json:5）。
- 测试规模：Rust `#[test]` **359 项** + 集成测试 4 个（`tests/fs_search.rs`、`git_operations.rs`、`shell_background.rs`）；前端 **70 个测试文件**（历史文档称 509 项，需跑通确认）。
- 质量设计（YAMET.md 明示并已核验）：功能性核心纯函数化 + 命令壳薄化；注释只讲 why；无 em-dash / 无 emoji；导入一律 `@/`。

## 二、Rust 后端源码调研

### 2.1 pty（`modules/pty/`）
- `Session`（session.rs）：字段 **drop 顺序刻意设计**——Windows 上先关 Job HANDLE（`KILL_ON_JOB_CLOSE` 杀整棵 pwsh 子树）再 killer/writer/master，避免 `ClosePseudoConsole` 在 conhost 排水时阻塞 Tauri 工作线程。
- 并发：Windows `CONPTY_LIFECYCLE_LOCK`（Mutex）串行化 ConPTY 的 create/close，注释直指 issue #356（重叠生命周期会冻结新控制台输出泵）；React 19 严格模式 dev 双挂载由该锁消化。
- 输出管道：reader 16KiB 读、flusher 首字节后 4ms 合并窗口（`FLUSH_COALESCE`）、`FLUSH_MAX_IDLE` 50ms 兜底；**背压上限 `MAX_PENDING` 4MiB**，溢出丢弃整段并注入 `ESC c` 硬复位 + 提示（避免把 CSI 序列截半破坏 xterm 屏幕状态）——这是"绝不序列化 mid-command 叶子"不变量的后端保证。
- `agent_detect.rs`：PTY 字节流过滤器，只认 OSC 序列驱动的 `yamet:agent-signal` 状态机（started/working/attention/finished/exited），重绘 TUI 不会抖动。
- `shell_init.rs`：Unix 注入 zshenv/zprofile/zlogin/zshrc/bashrc + fish `conf.d/yamet.fish`（OSC 7 + OSC 133 A/B/C/D）；Windows `profile.ps1` 包一层用户 prompt 函数；fish 4+ 用 `fish_features=no-mark-prompt` 去重。
- 挂载即流：`AiComposerProvider` 无条件挂 App 根（条件化会因 key 加载改变父元素类型、整体 remount、重spawn 全部 PTY）。

### 2.2 shell（`modules/shell/`）
- 三套语义分明：`shell_run_command`（oneshot，PowerShell `-NoProfile -Command` / Unix `$SHELL -lc`，共享 `build_oneshot_command`）；`shell_session_*`（跨调用持久 agent shell）；`shell_bg_*`（`background.rs`：`SharedChild` + **4MiB `BoundedRingBuffer`**，`Drop` 即 kill，退出码原子读取）。round-2 P0-3 的进程树杀（setpgid / Job Object）已落地于 oneshot 路径。
- 注意：round-2 报告遗留项"`shell_session_run` 超时未补进程树杀"需复核（本树未逐行验证 session.rs 的 kill 策略）。

### 2.3 workspace 授权注册表（`modules/workspace.rs`）
- `WorkspaceRegistry`：`authorize` 先 canonicalize 再入 set；`is_authorized` 用 `target.starts_with(root)`；`canonicalize_cached` TTL 1s、cap 256（面板刷新 ~100ms 突发合并 + TOCTOU 窗口收紧）。
- 两条授权路径语义不同：**AI/命令 spawn** 走 `authorize_spawn_cwd`（越界即拒）；**用户主动开终端**走 `authorize_user_spawn_cwd`（越界则登记为新根）。保存的 cwd 失效时回退 home（`user_spawn_cwd_or_home`）——终端必须能打开。

### 2.4 net（`modules/net.rs`）— AI HTTP 代理
- SSRF：`ip_kind` 覆盖 IPv4（link-local 元数据 169.254.169.254、loopback、RFC1918、CGNAT 100.64/10、benchmark 198.18/19）与 IPv6（loopback、AWS 元数据 `fd00:ec2::254`、fe80、fc00/7）；`resolve_and_classify` 取最差分类；**DNS 钉扎**——把通过判定的 IP 列表直接钉给 reqwest resolver，防重绑定。
- 头部黑名单（host/content-length/connection/proxy-*/transfer-encoding/upgrade 等 11 项）；URL 拒绝 userinfo；仅 http/https。
- **响应体上限 `MAX_RESPONSE_BYTES = 64MB`（net.rs:312）**——round-2 P0-4 已确认在树。
- 待核验项：`::ffff:` IPv4-mapped IPv6 无显式解包（grep `ffff` 无命中；旧树文档声称 net.rs:71-85 已修）。Rust `Ipv6Addr::is_loopback` 对 `::ffff:127.0.0.1` 返回 false，建议补一条单测钉死该边界。

### 2.5 secrets（`modules/secrets.rs`）
- OS keychain（`keyring` crate，service `yamet-ai`）+ Linux 文件 fallback（`#[cfg(target_os="linux")]`）。前端经 `secrets_*` 读写，密钥永不着盘/localStorage。gateway 凭据另存 `gateway:<platform>`。

### 2.6 ssh（`modules/ssh/`）— 第二轮 I3，已交付

## 四、安全模型评估（已核验）

| 边界 | 状态 | 证据 |
|---|---|---|
| AI 工具路径 deny（读+写、双层 canonical、NTFS/大小写/符号链接） | ✅ 强 | security.ts 全量 |
| shell 命令拦截（C0/bidi/rm -rf/dd/fork bomb/curl\|sh） | ✅ 强 | checkShellCommand |
| 出站 HTTP SSRF（IP 分类 + DNS 钉扎 + 头黑名单 + 64MB） | ✅ 强（1 项待核验） | net.rs |
| workspace 授权（spawn/LSP/git 门控） | ✅ | workspace.rs、git operations.rs、lsp session.rs、watch.rs:221 |
| 终端 agent 通知 OSC 信任 | ✅ 仅认 OSC 序列 | pty/agent_detect.rs |
| 预览 iframe 沙箱 + assetProtocol scope 空 | ✅ | tauri.conf.json |
| **fs_* 命令无工作区闸门** | ⚠️ 信任假设 | file.rs:58/128 无 is_authorized |
| **::ffff: IPv4-mapped IPv6** | ⚠️ 待核验 | net.rs 无显式解包 |
| 审批机制仅前端（AI SDK 暂停） | ⚠️ 设计边界 | tools.ts 9 处 needsApproval |

结论：底座安全设计与实现是生产级（尤其 security.ts 的规范化面与 net.rs 钉扎）；剩余项为"边界显式化 + 补测"，非漏洞坐实。

## 八、结论

工程地基仍是一流：PTY 背压 + Job Object 生命周期、SSRF 钉扎 + 64MB 上限、security.ts 双层 canonical deny、SSH argv 防注入、gateway 认证门禁 + 状态机测试、前端 509 项测试基线。第二轮 I1–I7 全部落地（SSH、拖放、项目感知补全、外部 agent 编排、网关打磨、文档对齐）。本轮最大的真实风险不是功能，而是**文档-代码漂移与发布链路**（provider 声称、版本节奏、updater 空端点、旧快照文档误导）。建议排期：P0-1/P0-2/P0-3 先清（安全边界 + 现实化 + 发布），随后 P1 的版本纪律与编辑器实时 FS 为高价值产品项。
