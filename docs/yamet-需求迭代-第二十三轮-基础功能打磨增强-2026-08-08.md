# 第二十三轮迭代需求：基础功能打磨增强

> 目标版本 **0.1.24**（功能性构建）。
> 用户命题：「基础功能打磨增强，迭代需求」。含义：对用户日常高频触碰的基础功能（AI 技能加载、MCP 连接、后台任务、终端会话重连、文件读写、SSH 远程、Onboarding）做系统性打磨——修真实竞态与资源泄漏、补数据安全缺口、统一平台体验。
> 范围：**概念模型 + 盘点核实 + 需求规划 + 实施方案**。

---

## §0 概念模型（先把现状搞清楚）

### 0.1 一句话总纲

基础功能 = 用户打开应用后**每天都会碰到**的那几条链路：AI 会话引导 → 技能/密钥加载 → 工具调用（文件/终端/SSH/MCP）→ 后台任务 → 会话恢复。前 22 轮把功能面铺得很广（终端/编辑器/DAP/MCP/LSP/网关/调度/Graph），但三份审计报告（audit-backend-core / audit-frontend / audit-user-ux，2026-08-07 基线）留下了一批**基础链路**上的真实缺陷：竞态、资源泄漏、数据安全窗口、平台差异。本轮只做这些"日常链路"的打磨，不碰新功能面。

## 需求规划（基础功能打磨 12 项）

| 缺口 | 动作 | 优先级 |

## 实施方案

### 依赖序

```
P0-1 技能竞态 → P0-2 MCP cwd → P0-3 bg 回收 → P0-4 pty id 竞态
→ P1-1 rename 竞态 → P1-2 sftp 分块 → P1-3 shell 并发 → P1-4 identity 空格
→ P2-1 死命令面 → P2-2 fs_write 上限 → P2-3 App ref → P2-4 Onboarding CTA
→ 构建
```

### P0-1 技能合并竞态（前端，小任务）

1. `useAiBootstrap.ts`：`await hydrate()` 之后再 `scanSkillsDir→mergeBuiltin`（同一异步块内串行）。
2. 补测试：mock `hydrate` 延迟，断言 mergeBuiltin 在 hydrate 后执行、builtin 不被覆盖。
3. 门禁：vitest + tsc。

### P0-2 MCP cwd 绑定（前端，小任务）

1. `mcp/lib/store.ts`：server 记录 `cwd`（添加/编辑时持久化）；`connect(id)` 用 server.cwd ?? 当前 root。
2. `McpSidebarPanel.tsx`：`connect(s.id)` 不再传当前 root。
3. 补测试：connect 使用 server 自带 cwd。
4. 门禁：vitest + tsc。

### P0-3 后台进程条目回收（后端，中任务）

1. `shell/mod.rs`：
   - `shell_bg_list`：过滤并 `remove` 已 exited 条目（`proc.is_exited()`）。
   - `shell_bg_kill`：kill 后 `remove`。
   - LRU 上限（如 64 条）：insert 时超限逐出最旧 exited / 最旧条目。
2. 补 Rust 测试：spawn 短命令 → list 后条目消失；kill 后移除。
3. 门禁：cargo test + clippy。

### P0-4 pty-helper 重连 id 竞态（后端，小任务）

1. `pty_helper/client.rs`：`List` 帧后不再 `sleep(200ms)`，改为在 reader 线程置一个 `Semaphore`/`Condvar`，`SessionList` 到达即放行（带 1s 超时兜底）。
2. 补测试：SessionList 晚到（>200ms）时 next_id 仍取全量 max。
3. 门禁：cargo test + clippy。

### P1-1 fs_rename Unix 覆盖竞态（后端，小任务）

1. `fs/mutate.rs`：Unix 用 `renameat2(RENAME_NOREPLACE)`（libc 调用，`#[cfg(unix)]`），失败 `EEXIST` → 报「already exists」；Windows 保留预检 + `rename`（天然不覆盖）。
2. 补测试：目标存在时报错、目标不存在成功、并发场景不覆盖。
3. 门禁：cargo test + clippy。

### P1-2 sftp_read 分块读（后端，小任务）

1. `ssh/sftp.rs`：先 `File::metadata` 预检大小，再 `take(READ_BYTE_CAP+1)` 分块读，超 cap 即报错，避免整体入内存。
2. 补测试：超大文件（模拟 ls size=0）被 cap 拦截。
3. 门禁：cargo test + clippy。

### P1-3 shell 并发上限（后端，中任务）

1. `shell/mod.rs`：`ShellState` 加 `Arc<Semaphore>`（8 并发），`shell_run_command`/`shell_session_run`/`shell_bg_spawn` 进入前 `acquire`。
2. 补测试：并发超限时排队而非拒绝（或按超时拒绝）。
3. 门禁：cargo test + clippy。

### P1-4 ssh identity_file 空格（后端，小任务）

1. `ssh/target.rs`：新增 `clean_identity_path`（拒空/控制符/前导 `-`，**保留空格**），`build_command` 中 identity_file 走它；host/user/port 仍走 `clean_component`。
2. 补测试：`C:\Users\John Doe\.ssh\id_ed25519` 放行；`-oProxyCommand=...` 仍拒。
3. 门禁：cargo test + clippy。

### P2-1 死命令面清理（后端，极小任务）

1. `lib.rs`：从 `generate_handler!` 移除 `pty_helper_list`、`pty_helper_start`（`client.rs:60` 内部仍以 Rust 函数调用 `pty_helper_start`，不受影响）。
2. 同步 `docs` 命令面（check-doc-drift 门禁）。
3. 门禁：cargo test + drift。

### P2-2 fs_write_file 字节上限（后端，极小任务）

1. `fs/file.rs`：`MAX_WRITE_BYTES = 64MiB`，`content.len() > cap` 直接拒绝。
2. 补测试：超限拒绝、正常写入放行。
3. 门禁：cargo test + clippy。

### P2-3 App 渲染期写 ref（前端，极小任务）

1. `App.tsx:196-197`：`const tabsRef = useRef(tabs);` + `useEffect(() => { tabsRef.current = tabs; }, [tabs])`。
2. 门禁：tsc + vitest。

### P2-4 Onboarding 能力 CTA（前端，小任务）

1. `OnboardingDialog.tsx`：`Feature` 卡片支持 `onClick`；aiKey 卡片点击 → `openSettingsWindow("models")`；capabilities 卡片 → `openSettingsWindow("integrations")`；terminal/editor/ai 卡片 → 关闭引导（对应 surface 已落地）。
2. 补 i18n 键（若需提示文案）。
3. 门禁：tsc + vitest + i18n-scan。
