# 第十六轮迭代需求：平台抽象层迁移（GUI/WebUI/TUI/CLI 共享核心）

> 目标版本 **0.1.17**（功能性构建，四文件同步：`package.json` / `tauri.conf.json` / `Cargo.toml` / `Cargo.lock`）。
> 本文是**平台抽象层迁移的执行方案**。本轮不新增功能，只做架构交付。
> 铁律：① 所有平台入口（`@tauri-apps/*`）必须收敛到 `@/platform` 统一适配器层；② 前端功能模块**零 import from @tauri-apps/* 直接引用**；③ `pnpm build` + 全量测试在每批迁移后必须通过。
> 前置：第十五轮（0.1.16）已交付——AI 聊天窗口 6 项 P0 补强，构建通过。

---

## 0. 本轮定位

**架构铁律**（`src/platform/index.ts:7` 已写明）：「Feature modules import from here: `import { platform } from "@/platform"`. No feature code should import from `@tauri-apps/*` directly.」

`src/platform/` 是一个设计完整的**平台抽象层**：
- **16 个标准接口**（`types.ts`）：`IIpcAdapter` / `IStorageAdapter` / `IEventAdapter` / `IPathAdapter` / `IWindowAdapter` / … `IClipboardAdapter` / `IWatchAdapter`
- **Tauri 实现**：16 个适配器全部完成（`platform/tauri/*.ts`）
- **Web 实现**：已有 ipc/storage/events/window/os/clipboard 模块 + `noopAdapter`（dialog/opener/notification/autostart/process/updater 在浏览器不可用）
- **入口**：`detectPlatform()` → 选择 tauriAdapter（`__TAURI_INTERNALS__`）或 webAdapter → 缓存

**但迁移仅 0.7% 完成**：136 处引用直接 import `@tauri-apps/*`，仅 2 处（composer.tsx、platform/index.ts）使用 `@/platform`。

**本轮目标**：把 136 处 `@tauri-apps/*` 直接引用全量迁移到 `@/platform`，**所有功能模块零 Tauri 直接依赖**。GUI（Tauri 桌面）、Web 浏览器、未来 TUI/CLI 通过换适配器实现同一核心逻辑。

## 3. 需求定稿

### P0 · 迁移 API 层：`import { invoke }` / `import { Channel }` → `@/platform`
**目标**：消除 56 处 `@tauri-apps/api/core` 引用。
- 当前 `@/platform` 已导出 `invoke` 和 `Channel`（`index.ts:68`）
- 迁移：每个文件将 `import { invoke, Channel } from "@tauri-apps/api/core"` 改为 `import { invoke, Channel } from "@/platform"`
- **风险**：`Channel` 在 web 模式下不对应 Tauri Channel（`types.ts` 的 `IIpcAdapter.createChannel` 需适配）
- **方案**：分 4 批迁移——先低风险文件（无 test）、再高风险（settings/sessions）、最后测试文件

### P0 · 迁移事件层：`import { listen, emit }` → `platform.events`
**目标**：消除 13 处 `@tauri-apps/api/event` 引用。
- `platform.events.listen()` / `platform.events.emit()` 已实现（tauri/events.ts + web/events.ts）
- **方案**：每处改为 `const { events } = getPlatform(); await events.listen(...)`

### P0 · 迁移存储层：`LazyStore` → `createStorage`
**目标**：消除 8 处 `@tauri-apps/plugin-store` 引用。
- 当前 `createStorage(filename)` 返回 `IStorageAdapter`（`get/set/delete/entries/save/onChange`）
- **差距**：`LazyStore` 的 `new LazyStore(path, {defaults, autoSave})` → 需改为 `createStorage(path)` 并处理 `await storage.init()`
- **方案**：每处 store 文件（settings、chat、spaces）适配新 API；`autoSave` 语义通过定时 flush 或 `onChange` + debounce 替代

### P0 · 迁移窗口/路径/开盖/通知等
| 层 | 引用数 | 迁移目标 |
|---|---|---|
| `@tauri-apps/plugin-opener` | 12 | `platform.opener.openUrl/revealItemInDir` |
| `@tauri-apps/api/window` | 9 | `platform.window.*` |
| `@tauri-apps/api/path` | 8 | `platform.path.homeDir/join/appConfigDir` |
| `@tauri-apps/api/webviewWindow` | 7 | `platform.webview.*` |
| 其余（dialog/notification/os/app） | 16 | 对应适配器 |

## 4. 规划方案

### 4.1 架构终态
```
src/platform/
├── types.ts          ← 16 接口定义（不变）
├── index.ts          ← detectPlatform() + getPlatform() + invoke + createStorage + Channel
├── tauri/            ← 16 适配器（全部完整，不变）
│   ├── ipc.ts / storage.ts / events.ts / path.ts / window.ts / webview.ts
│   ├── os.ts / dialog.ts / opener.ts / notification.ts / autostart.ts
│   ├── process.ts / updater.ts / clipboard.ts / watch.ts
│   └── index.ts      ← tauriAdapter 组合
└── web/              ← web + noop（已有基础）
    ├── ipc.ts / storage.ts / events.ts / window.ts / os.ts / clipboard.ts
    ├── noop.ts       ← dialog/opener/notification/autostart/process/updater 不可用
    └── index.ts      ← webAdapter 组合

← 所有功能模块 import from @/platform
← src/platform/tauri/ 自身可引用 @tauri-apps/*（唯一例外）
```

### 4.2 迁移策略
- **每批迁移 1 个 API 层**，全部文件批量替换后立即 `pnpm build` + `pnpm test` 验证
- **存储层（LazyStore→createStorage）** 是**唯一有 API 差异**的迁移，需逐文件适配
- **其余层**（invoke/events/window/path/opener 等）是**纯替换**，参数签名一致

### 4.3 存储 API 映射
```
new LazyStore(path, {defaults, autoSave})   →  createStorage(path)
store.set(key, value)                       →  storage.set(key, value)  ✅ 一致
store.get(key)                              →  storage.get(key) ✅ 一致
store.entries()                             →  storage.entries() ✅ 一致
store.delete(key)                           →  storage.delete(key) ✅ 一致
autoSave: 200                               →  需手动 flush（onChange + debounce timer）
onChange(cb)                                →  storage.onChange(cb) ✅ 实现
```
