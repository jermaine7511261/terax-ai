## 〇、总评

第六轮交付了 AI 生态接入面（外部工具接入 MCP client、技能化复用、记忆可管理）。第七轮把 YaMet 从"消费外部能力"推进到"**对外输出能力 + 内部自动化**"：
- **反向 MCP server（★ L1 LangBot）**：YaMet 自身能力（文件/搜索/git）以 MCP server 形态暴露，外部 agent（Claude Code / OpenCode 等）可经 `mcpServers` 接入——与第六轮 MCP client 天然互补。
- **跨会话语义检索（★ H1 Hermes）**：agent 可检索历史会话与记忆条目，实现跨会话回忆。
- **cron 定时自动化（★ H3 Hermes）**：内置调度器，自然语言定义定时任务并投递。
- **命令执行目标（★ H4 Hermes）**：`bash_run` 支持 `target`（先做 Docker）。
- **skills 自动沉淀（★ H2 Hermes）**：长任务后 agent 可调用 `create_skill` 沉淀可复用技能。
- **调研（★ T1 Terax）**：diff 上游功能增量，产出吸收清单。

插件系统维持 out of scope；DAP/集成调试器维持 ROADMAP out of scope（仅记录方向性参考）。

## 〇·一、全量测试覆盖率提升（P0 · 本轮优先）

**目标**：显著提升全量测试覆盖率（基线：11.76% 语句 / 11.16% 分支 / 7.41% 函数），优先覆盖可测的纯逻辑模块，并评估引入组件测试环境覆盖核心 UI。本项为**需求文档层面落定**，实施前需用户确认范围与依赖取舍，不擅自行动。

**现状（2026-08-04 实测）**：全项目 11.76% 语句。低覆盖主因：
- **UI 组件（`.tsx`）**：设置页/AI 面板/编辑器等占文件多数，无 jsdom 测试环境，几乎 0%；
- **tauri invoke 薄封装**：`native.ts` / `keyring.ts` / `proxyFetch.ts` 等绑定层（1-5%）；
- 已补测的核心纯函数：`lib/transport.ts` 3.5%→54.9%、`tools/memory.ts` 92.9%、`lib/mcp.ts` 75%、`lib/snippets.ts` 72%（574 用例全绿）。

**方案**：

1. **纯逻辑补测（无新依赖，vitest 原生 mock）**：`lib/`（utils、fonts、sessions、todos、modelPrefs、config、security、compact、errors、agents、slashCommands）、`store/`（memoryStore、snippetsStore、mcpStore，mock `lib/mcp`/`LazyStore`）、`tools/`（shell、fs、git、todo、context 的 execute 校验分支，mock native + ctx）。预计全量语句 ≥ 20%。
2. **组件测试环境（需评审）**：引入 `jsdom` + `@testing-library/react`，覆盖设置页（SkillsMcpSection、AgentsSection、GeneralSection）与 AI 面板（AiToolApproval、SnippetPicker、composer）核心渲染/交互。**新增依赖与「始终轻量」主题存在张力，由用户确认后再实施**。
3. **门槛**：本轮 P1/P2 功能均须带测试；覆盖率纳入 `pnpm verify`（可选运行，不阻塞构建）。

**验收**：
- [ ] 纯逻辑补测后全量语句覆盖 ≥ 20%（基线 11.76%），分支 ≥ 18%
- [ ] 组件测试环境经用户确认引入后，核心设置页/AI 组件渲染测试覆盖其可测分支
- [ ] `pnpm test` 全绿；`pnpm check-types && pnpm lint` 全绿

## 一、反向 MCP server（P1 · ★ L1 LangBot）

**目标**：YaMet 以 MCP server 形态对外暴露只读能力，外部 agent（Claude Code / OpenCode / grok 等）经 `mcpServers` 配置接入。

**现状**：`src-tauri/src/modules/mcp/` 是 MCP client（第六轮）；无 server 侧实现；`main.rs` 无 CLI 分支。

**方案**：

1. **`src-tauri/src/modules/mcp_server/`**：
   - `protocol.rs`：MCP server 侧 JSON-RPC 2.0（stdio 换行分隔）——`initialize` / `notifications/initialized` / `tools/list` / `tools/call` / `ping`，协议编解码纯函数。
   - `tools.rs`：只读工具注册表（`read_file` / `list_directory` / `grep` / `glob` / `git_status` / `git_diff`），inputSchema 与 MCP 规范对齐；**只读默认，不暴露写工具**（写操作需客户端侧显式授权，MCP 无审批通道，保守不做）。
   - `mod.rs`：`run_server(workdir)` 主循环——读 stdin 行 → 分发 → 写 stdout；路径校验（解析相对 workdir，拒绝越界）；输出上限（32 MiB）；请求超时。
2. **CLI 入口**：`main.rs` 检测 `__mcp_server` 参数 → 以阻塞模式运行 server（`cwd` 取启动目录或环境 `YAMET_MCP_CWD`）。
3. **外部接入**：Claude Code `~/.claude.json` `mcpServers.YaMet = { command: "YaMet", args: ["__mcp_server"], cwd: "<workspace>" }`。
4. **安全边界**：只读工具 + 路径限制在工作目录内（仿 fs 授权语义）；`read_file` 大小上限；`grep` 排除 `.git`。

**验收**：
- [ ] `cargo check/clippy/test` 全绿；新增 `mcp_server/` 单测（协议编解码、路径越界拒绝、工具 schema）
- [ ] `YaMet __mcp_server` 可被外部 MCP client 连接：`tools/list` 返回 6 个只读工具，`tools/call read_file/grep` 正常工作
- [ ] 越界路径（`../`）与超限文件被拒绝；`.git` 不出现在搜索结果

## 二、跨会话语义检索（P1 · ★ H1 Hermes）

**目标**：agent 工具 `search_memories(query)` 检索历史会话与记忆条目，结果摘要注入上下文，实现跨会话回忆。

**现状**：会话历史列表已有（第五轮 U1，`src/modules/ai/lib/sessions.ts`）；记忆两级（会话内 `memoryStore` + YaMet.md 落盘）；无检索工具。

**方案**：

1. **数据源**：历史会话（`sessions.ts` `loadAll`/`loadMessages`，含每条消息文本）+ 记忆（`getSessionMemory` + YaMet.md managed block）。
2. **`src/modules/ai/tools/searchMemories.ts`**：`search_memories(query)`——关键词/子串匹配历史会话消息与记忆条目，按相关度取 top N（默认 8），返回带会话标题/时间戳的摘要列表（截断正文）。
3. **注入**：`buildTools` 并入；`needsApproval: false`（只读检索）；结果过 `redactSensitive`。
4. **上限**：单次扫描会话数上限（如最近 200 会话）；单条正文截断（200 字符）；避免上下文膨胀。

**验收**：
- [ ] agent 可调用 `search_memories(query)` 返回匹配的历史会话片段与记忆条目摘要
- [ ] `pnpm test` 新增：检索匹配/排序/截断纯函数用例
- [ ] `pnpm check-types && pnpm lint && pnpm test` 全绿

## 三、cron 定时自动化（P2 · ★ H3 Hermes）

**目标**：内置调度器，自然语言定义定时任务（每日报告/每周审计），到点 spawn agent，结果投递（通知/IM/新会话）。

**现状**：无调度能力；通知基建已有（`tauri-plugin-notification` + 前端 toast）。

**方案**：

1. **`src-tauri/src/modules/scheduler/`**：tokio 调度器（`tokio::time::interval` 逐秒 tick + cron 表达式解析——无新依赖，自实现 5 字段 cron 子集或接入 `cron` crate；倾向自实现轻量子集保"始终轻量"）。
2. **任务定义**：`{ id, name, prompt, schedule(cron), target: "notification" | "im" | "session", enabled }` 持久化到 preferences（`tauri-plugin-store`）。
3. **触发**：到点经 `spawnManagedAgent`（复用现有 agent 基建）执行 prompt，结果按 target 投递。
4. **前端**：设置页新增「定时任务」区（或命令面板），增删改/启停任务，下一次触发时间预览。

**验收**：
- [ ] `scheduler/` 单测：cron 解析（每分钟/每小时/每日/每周）、下一次触发计算、任务去重
- [ ] 设置页可增删改/启停任务；到点触发 agent 并投递结果
- [ ] `pnpm test` / `cargo test` 全绿

## 四、命令执行目标扩展（P2 · ★ H4 Hermes）

**目标**：`bash_run`/`shell_session` 支持可选 `target`（local / docker exec / ssh host），先做 Docker。

**现状**：`bash_run` 仅 local（`tools/shell.ts` → `shell_run_command`）；SSH 终端 + WSL 工作区已有。

**方案**：

1. **`tools/shell.ts`**：`bash_run` inputSchema 增加可选 `target: { type: "docker", image: string }`；`buildShellTools` 内做目标分派。
2. **Rust `shell/mod.rs`**：`shell_run_command` 增加 `target` 参数——`docker exec <image> <command>`，校验镜像名（`[a-z0-9][a-z0-9._/-]*`，拒绝标签注入）与命令守卫（复用 `checkShellCommand` + Rust 侧校验）；`docker` 不存在时报明确错误。
3. **安全**：镜像白名单式校验（不允许 `-` 开头参数）；执行目标记录日志。

**验收**：
- [ ] `bash_run` 带 `target.docker` 时经 `docker exec` 执行；非法镜像名被拒绝
- [ ] 单测：镜像名校验、目标参数构造纯函数
- [ ] 本机无 docker 时报"docker 不可用"而非悬挂

## 五、skills 自动沉淀（P2 · ★ H2 Hermes）

**目标**：长任务完成后 agent 可选调用 `create_skill(name, prompt, toolAllowlist)` 沉淀可复用技能（走审批），与既有 `skills/` 目录 / 设置页启停打通。

**现状**：`skills/` 目录扫描 + `mergeBuiltin`/`toggleBuiltin`（第六轮）；无创建工具。

**方案**：

1. **`src/modules/ai/tools/createSkill.ts`**：`create_skill(name, prompt, toolAllowlist?, handle?)`——`needsApproval: true`；校验字段（name/prompt 非空、handle 合法）；写入 `<workspace>/skills/<name>/skill.json`（经 `native.writeFile` + workspace 授权），随后 `scanSkillsDir` 刷新 store。
2. **约束**：与用户自建 snippet 的 handle 冲突时拒绝或加后缀；写入需 workspace 存在。
3. **接入**：`buildTools` 并入；设置页既有「内置 skills 列表」自动出现新沉淀技能（可启停）。

**验收**：
- [ ] agent 调用 `create_skill` 后 `skills/<name>/skill.json` 落盘，设置页内置列表出现该技能（可禁用）
- [ ] 校验失败（空 name/prompt、非法 handle、无 workspace）返回明确错误
- [ ] `pnpm test` 新增：字段校验、handle 冲突纯函数用例
