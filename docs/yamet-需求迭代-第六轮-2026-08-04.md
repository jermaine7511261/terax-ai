## 一、MCP client 接入（P1）

**目标**：YaMet agent 可连接外部 MCP server（stdio / SSE / HTTP），把远端工具动态注册进现有 AI 工具面，复用 `needsApproval` 审批流与 `security.ts` 守卫。

**现状**：`src/` 与 `src-tauri/src/` 全库 `grep mcp` 均 0 命中。AI 工具由 `tools/tools.ts` 的 `buildTools(ctx)` 组装；审批卡渲染在 `AiToolApproval`；审批流与 auto-approve 已成熟。

**方案**：

1. **技术选型（建议 Rust 侧 `rmcp`）**：
   - 进程生命周期（stdio 子进程 spawn/kill/断线重连）天然归 Rust，复用 `shell_bg` 的 spawn 基建与进程树管理（★ C2 claude-code-haha：stdio 子进程型 MCP server 为 Claude Code 生态主流形态）。
   - 工具 schema 经 tauri 命令透传前端，避免 TS SDK 在渲染进程里维持连接。
   - 备选 TS 侧 `@modelcontextprotocol/sdk`：仅在纯前端传输场景考虑，本项目不适用。
2. **后端 `src-tauri/src/modules/mcp/`**：
   - `mcp_connect(config)`：按传输类型 spawn stdio 子进程（命令经 `checkShellCommand` 校验）或建立 SSE/HTTP 连接；完成 `initialize`/`initialized` 握手；拉取 `tools/list` 存入 schema 注册表（`RwLock<HashMap<client_id, McpClient>>`）。
   - `mcp_tools_list` / `mcp_call(client_id, tool, args)`：`tools/call` 经 JSON-RPC 转发，结果（含 `isError`、结构化内容）回传前端。
   - 生命周期：`Drop` 即 kill 子进程；连接中断自动重试（有限次数 + 退避，仿 `shell/background.rs`）；每客户端并发上限。
   - 传输类型：stdio（命令 + 参数 + cwd + env）优先，SSE/HTTP（URL + headers）次之。
3. **前端接入**：
   - 设置页新增「Skills / MCP」统一配置区（★ 参考 Xora / LangBot）：一个入口管理 MCP servers（名称、传输类型、命令/URL、参数、环境变量）与 snippets/skills，避免分散配置；持久化到 preferences（`tauri-plugin-store`）。
   - `buildTools(ctx)` 动态并入已连接 MCP server 的工具：schema JSON Schema → zod（复用既有 zod 工具定义模式），全部套 `needsApproval: true`（远端工具不可信，默认人工门禁；可被既有 remember 机制豁免）。
   - `ai-elements/tool.tsx` 扩展：新增 MCP 工具卡类型，显示 server 来源名，失败态展示 `isError` 与 stderr 尾（★ Xora Code / claude-code-haha：工具调用卡显示来源与参数摘要）。
4. **安全边界**（★ C3 claude-code-haha：权限安全设计分层，与 YaMet security.ts + 审批流同构；★ X3 Xora Code：凭据/权限裁决不放渲染页面）：
   - 所有 MCP 工具默认 `needsApproval: true`；参数经 zod 校验后再转发，防注入。
   - stdio 命令经 `checkShellCommand`（`security.ts`）；SSE/HTTP 目标复用 `net.rs` 的 IP 分类（本地/远程都允许但记录日志，仿本地 LLM 端点处理）。
   - 工具结果过 `redactSensitive` 脱敏（复用会话持久化脱敏逻辑）。
5. **验收**：
   - 配置一个本地 MCP server（filesystem 或 DB demo），agent 能列出并调用其工具，调用前弹审批卡，拒绝/批准行为与内置工具一致。
   - server 退出或断线后，工具自动从列表移除，调用报错提示而非悬挂。
   - 版本：随 **0.1.7** 功能性构建（四处同步）。

## 二、Skill 升级（P2）

**目标**：snippets 升格为「prompt 片段 + 可选工具白名单」的 skill，覆盖 ROADMAP「AI tools / snippets as installable bundles」未勾项（bundle 化留后续）。

**现状**：`snippetsStore.ts` + `lib/snippets.ts`；`Snippet` 仅含 prompt 文本；composer `#handle` 拾取；无工具绑定、无 bundle 概念。第五轮已统一文档用词（Skills → snippets）。

**方案**：

1. `Snippet` 类型扩展：
   ```ts
   type Snippet = {
     id: string;
     name: string;
     description: string;
     prompt: string;
     toolAllowlist?: string[];  // 引用工具 id，如 ["read_file","grep","bash_run"]；缺省 = 仅 prompt
   };
   ```
2. **注入层**（★ C2 claude-code-haha：Skills 支持工具绑定；★ H2 Hermes：skill 含工具面约束）：composer 触发 `#handle` 时，若 snippet 带 `toolAllowlist`，本次会话的 `buildTools(ctx)` 按白名单过滤工具集，实现"技能限定工具"语义（区别于主 agent 全量工具）。
3. **UI**：「Skills / MCP」设置区（见一.3）内嵌 snippet 编辑器，加工具多选（选项来自工具注册表 `tools/tools.ts` 的工具 id + 描述）。
4. **内置 skills 目录约定**（★ 参考 LangBot `skills/` 单一事实来源）：仓库新增 `skills/` 目录，每个 skill 一个 `skill.json`（name/description/prompt/toolAllowlist）+ 可选说明文件；应用启动时扫描目录并入 snippets store（与用户自建 snippets 合并，内置可禁用）。这为后续 bundle 分享铺路。
5. **开放标准兼容性评估**（★ 参考 Hermes agentskills.io）：实现后评估与 agentskills.io 类开放 skill 标准（SKILL.md 规范）的映射成本，仅产出评估结论，不做标准实现。
6. **持久化**：沿用 `snippetsStore`（`tauri-plugin-store`），迁移逻辑兼容旧数据（无 `toolAllowlist` 字段 = 仅 prompt）。

**验收**：建一个仅含 `grep`/`read_file` 的 review skill，该技能会话下 agent 不可用 `write_file`/`bash_run`；内置 `skills/` 目录出现即被识别，可禁用；切换普通会话恢复全量工具。
**版本**：随 0.1.7 穿插。

## 三、记忆系统增强（P2）

**目标**：现有 `update_project_memory` 两级记忆（会话内 store + YAMET.md 落盘）基础上，补**可管理性**（浏览/编辑/删除）、**边界保护**（上限、去重）与**主动沉淀**（nudge）。

**现状**：`src/modules/ai/tools/memory.ts:18` `update_project_memory`（含 id 替换 + `memory.test.ts`）；YAMET.md 启动时注入；`YAMET_MD_MAX_BYTES` 上限常量在 transport.ts；会话内累积 `memoryStore`。

**方案**：

1. **记忆浏览/编辑 UI**：设置页新增「项目记忆」区（或命令面板 `memory.open`）：
   - 展示当前工作区 YAMET.md 内容 + 会话内记忆条目（按来源分组：**手动写入** vs **自动沉淀**，★ 参考 Hermes 主动记忆），只读预览 + 手动编辑。
   - 编辑写回 YAMET.md，走 `security.ts` 可写校验与 mtime 冲突检查（复用编辑器保存逻辑）。
2. **工具扩展**：`update_project_memory` 增加 `delete_project_memory(id)` 与 `list_project_memory()`（无参列出条目）；沿用 id 替换语义。
3. **主动沉淀 nudge**（★ 参考 Hermes periodic nudges）：
   - 会话收尾或长任务结束（`agentMeta` 状态回到 idle 且会话有实质产出）时，composer 区出现一次性轻提示"把要点写入项目记忆？"。
   - 确认后调 `update_project_memory`（走审批），条目标记来源 `auto`（可手动删除）。
   - 默认关闭（设置项 `memory.nudge`），避免打扰。
4. **边界保护**：超 `YAMET_MD_MAX_BYTES` 时工具返回明确错误（而非截断）；条目去重沿用现有合并逻辑；条目数上限（如 50 条）防失控。
5. **项目隔离（可选）**：按 workspace root 键控记忆文件，列可选。

**验收**：设置页可查看/编辑当前项目记忆并按来源分组；agent 能删除单条记忆；nudge 开启时会话收尾出现提示、确认后落盘且标记来源；超限有明确报错；现有 `memory.test.ts` 覆盖新工具。
**版本**：穿插随 0.1.7。

## 四、方向决策

- **插件系统：维持 out of scope。** ROADMAP「Extension marketplaces at IDE scale」已明示；任意 UI/行为扩展不做。MCP client 是外部工具接入（数据面），Skill 是内部技能复用（提示面），均不构成插件市场，与「轻量、终端优先」一致（★ C2 claude-code-haha 佐证：MCP + Skills 双系统即可覆盖，插件市场不在范围）。
- **参考项目边界**：第七轮候选（反向 MCP server、跨会话语义检索、cron 定时自动化、命令执行目标、skills 自动沉淀、ACP、DAP）见 `docs/yamet-参考项目调研与迭代需求-2026-08-04.md`，本轮不实施。
- **ROADMAP 同步**：「规划中」新增/勾选：MCP client 接入、Skill 升级（snippets + 工具白名单）、记忆系统增强；「更远期」保留 bundle 化。
