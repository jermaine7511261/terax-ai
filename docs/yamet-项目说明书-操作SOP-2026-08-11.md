## 二、架构关键链（新增能力的落点）

### 1. AI 工具注册链（前端）

```
registry.ts (静态清单, settings 渲染 toolAllowlist)
   └─ tools.ts buildTools(ctx) → 各 builder（fs/git/edit/search/shell/subagent/computer/fusion/memory/net…）
         └─ execute 内调用 native.*（Rust 桥）
```

- 新增工具 = ① builder 文件 → ② `tools.ts` 加 `...buildXxxTools(ctx)` → ③ `registry.ts` 加 `{id, description}`
- **registry.ts 不得 import 工具实现**（settings 急切引用预算，eager-budget.test.ts 锁死）
- 审批：mutating 工具 `needsApproval: true`；子 agent 内 writable 工具经 `stripApproval` 解封

### 2. Rust 命令注册链（后端）

```
src-tauri/src/modules/<mod>/<file>.rs   #[tauri::command] fn xxx()
   └─ src-tauri/src/modules/<mod>/mod.rs  pub mod <file>;
   └─ src-tauri/src/lib.rs                use modules::{...}; + generate_handler![mod::xxx, ...] + .manage(State)
   └─ src/modules/ai/lib/native.ts        native.xxx = invoke("xxx", {...})   ← 前端桥
```

- **每一步缺一不可**：漏 `generate_handler!` 命令不注册；漏 native.ts 桥前端调不到
- `scripts/check-doc-drift.mjs` 会校验 命令↔docs 漂移

### 3. 安全门禁（新增命令必须过）

```
guardrails.rs 链（ToolCall hook，先失败短路，panic fail-closed）：
  ShellCommandGuard（禁空/控制字符）→ SensitivePathGuard（.env/.ssh/keys）→ ComputerUseGuardrail（截图限频/坐标边界/敏感文字）
fs 授权：enforce_ai_workspace_authorization（AI 源写必须落授权 workspace；敏感路径防绕过）
keyring：密钥只在 Rust 侧解析（secrets::read_key，KEYRING_SERVICE="YaMet-ai"），前端只见 account 名
```

## 六、前端功能配置 SOP

### 6.1 配置架构（三层）

```
┌─ ① Preferences 类型 + 默认值   src/modules/settings/store.ts  (interface Preferences + defaults)
├─ ② 持久化 KEY_ 常量            store.ts  (KEY_THEME = "theme" … 约 60 个)
├─ ③ zustand store 壳            src/modules/settings/preferences.ts  (usePreferencesStore, init() 水合)
└─ ④ 消费点                      各 section UI (src/settings/sections/*) + 运行时模块
密钥（API key）单独走 keyring      src/modules/ai/lib/keyring.ts + Rust secrets (Rust 侧解析，前端只见 account 名)
```

**数据流**：设置页 section 修改 → `usePreferencesStore.setState` → 持久化到 tauri-plugin-store（`key=value`，KEY_ 常量做 key）→ 下次启动 `init()` 水合恢复。

**关键约束**：
- 配置持久化 key 一律用 `KEY_*` 常量，不得散落字符串字面量
- 密钥（apiKey/token）**绝不进 Preferences**，走 keyring（`secrets_get/set` 桥）
- 新配置项默认值放 `store.ts` 的 defaults 对象（新增字段**必须**补默认值，否则水合后 undefined 引发运行时错误）

### 6.2 新增一个配置项 SOP（6 步）

以新增 `terminalCursorStyle` 为例：

1. **`store.ts` Preferences 接口**加字段：
   ```ts
   terminalCursorStyle: "block" | "line" | "underline";
   ```
2. **`store.ts` 加 KEY_ 常量**：
   ```ts
   const KEY_TERMINAL_CURSOR_STYLE = "terminalCursorStyle";
   ```
3. **`store.ts` defaults 补默认值**（缺这一步水合即坏）：
   ```ts
   terminalCursorStyle: "block",
   ```
4. **`store.ts` persist 映射**：找到该字段的持久化读写处（`loadPreferences`/`savePreferences` 或 set 封装），接入 KEY 常量。
5. **设置页 UI**：`src/settings/sections/EditorSection.tsx`（或对应域 section）加 `SettingRow` + 控件（Select/Toggle/Slider），写 `usePreferencesStore`。
6. **i18n**：`src/lib/i18n/translations.ts` 补 label/desc（zh + en），跑 `pnpm i18n-scan` 校验 key 完整。

> ⚠️ 验证：`npx tsc --noEmit` + `pnpm test`（store.test.ts 会校验 defaults 完整性）。

### 6.4 模型 / Provider 配置 SOP

#### 新增一个 provider（如新增 "xai"）

1. `src/modules/ai/config.ts`：`ProviderId` 联合类型加 `"xai"` → `PROVIDERS` 数组加条目（id/label/keyringAccount/keyPrefix/consoleUrl）→ `MODELS` 加该 provider 的模型（id/name/context）
2. `src/modules/ai/lib/keyring.ts`：`ProviderId` 对应 keyring account（Rust 侧 `secrets` 已支持任意 account，通常无需改 Rust）
3. `src/settings/sections/ModelsSection.tsx`：provider 卡片/选择器若按 PROVIDERS 渲染则自动出现
4. `src/lib/i18n/translations.ts`：provider label 补 zh/en
5. 验证：`npx tsc --noEmit` + `pnpm test`（providerModels.test.ts）

#### 配置降级链（§3.2）

- 前端：`providerFallbackChain: string[]`（ModelsSection 拖拽排序，R29 §3.2.2）
- 后端：Rust `resilience.rs` CircuitBreaker 消费 provider id；`is_provider_available` 决定跳过后端
- 设置页显示熔断器状态需调 `resilience_status` 类命令（尚未接线，前端仅存顺序）

#### 密钥管理

- 密钥只存 keyring：`secrets_set(keyringService="YaMet-ai", account, value)`
- 前端 `getAllKeys()` 返回 `ProviderKeys = Record<ProviderId, string|null>`（仅存在性，不读取明文）
- AI 工具/子代理通过 `keys` 参数 + `buildConfiguredLanguageModel(modelId, keys, …)` 建模型

### 6.5 快捷键配置 SOP

1. `src/modules/shortcuts/shortcuts.ts`：
   - `ShortcutId` 联合类型加 id（如 `"terminal.newLine"`）
   - `SHORTCUTS` 数组加条目：`{ id, label, group, defaultBindings: [{ key, ctrl?, meta?, alt?, shift? }] }`
   - `SHORTCUT_GROUPS` 分组（无新组可跳过）
2. 消费点：全局 keydown 分发（`src/modules/shortcuts/` 的 dispatch）按 id 匹配执行；编辑器内快捷键注意与 CM6 keymap 冲突（editor.undo/redo 走 CM historyKeymap）
3. 设置页 ShortcutsSection 自动渲染（按 SHORTCUTS 遍历）
4. i18n：label 补 zh/en

### 6.6 i18n SOP

- 结构：`src/lib/i18n/translations.ts`（zh + en 两个对象，key 同名；每 key 形如 `{ editorDesc: "…" }`）
- 新增 key：两个语言对象**同时**补，缺一 `pnpm i18n-scan` 报错
- 运行 `pnpm i18n-scan` 校验完整；`useI18n()` hook 消费
- 配置项 label/desc 统一走 i18n，不硬编码中文（设置页 section 同理）

### 6.7 常见配置故障排查

| 症状 | 根因 | 修法 |
|---|---|---|
| 设置不生效/重启丢失 | 新字段没接 KEY_ 常量或没进 persist 映射 | 补 6.2 第 2/4 步 |
| 水合后字段 undefined → UI 崩 | defaults 缺默认值 | store.ts defaults 补默认值 |
| 设置页新增项不出现 | 没注册到对应 section 或 SettingsApp tab | 检查 section 是否被 SettingsApp 引用 |
| provider key 不识别 | keyPrefix 校验失败 / account 名不匹配 config.ts | 核对 keyringAccount 与存入的 account |
| 快捷键无响应 | ShortcutId 加了但 dispatch 未消费；或与 CM6 keymap 冲突 | shortcuts 模块加 handler；编辑器快捷键走 CM keymap |
| i18n-scan 报缺 key | 只补了一种语言 | zh/en 同时补 |

## 七、陷阱清单（Windows 环境实测）

| # | 陷阱 | 规避 |
|---|---|---|
| 1 | 项目文件多为 **CRLF**，`edit` 工具跨行 old_string 匹配失败 | 整文件 `write_file` 重写，或 node 脚本按行打补丁（`fs.readFileSync` 保留原行尾）|
| 2 | 同一文件连续多次 `edit` 可能**丢失第一个变更** | 每文件一次 `multi_edit` 批量完成，或单次编辑后重读 |
