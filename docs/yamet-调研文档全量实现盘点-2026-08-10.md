## 四、有效建议（按性价比排序）

1. **【P0】关闭 WebUI M1 三个 MUST**（见 08-10 四视角报告第 6 节）：WS 绑 127.0.0.1 + Origin/token 鉴权、fs 路径包含校验 + 敏感文件门、收敛写面（删 fs_write_file/delete/rename 或补门）。这是当前唯一高危敞口。
2. **【P1】补 PraisonAI 剩余 SHOULD 中最高性价比的三项**：
   - S4 Todo 依赖（dependencies + getReadyItems）：让 graph 编排的 todo 可表达"前序完成才能并行推进"，纯前端 ~1–2 天；
   - S5 AutoMemory 正则提取层 + rules glob 激活：当前记忆只做词面量/2-gram 匹配，加一层"`i prefer X` → preference"正则提取 + CLAUDE.md/AGENTS.md 按 glob 激活，让记忆与项目规则从"被动 nudge"变"主动注入"；
   - S1 doom-loop 恢复策略：检测已有，缺"换路径 → 换模型 → 询问用户"分级恢复，检测不恢复等于只报错。
3. **【P1】agentskills 转换器**：SKILL.md → skill.json 一次性转换脚本（frontmatter + body + toolAllowlist 映射），几小时工作量，换来 agentskills.io 生态全部技能可导入。
4. **【P2】IM 微信/QQ 媒体下载补齐**：dingtalk 已有 MediaItem 范式，微信/QQ 适配器照抄。
5. **【P2】建"调研待办池"**：PraisonAI 这类调研的 S2/S3/S6/S7/N1–N6 目前无归属追踪，容易沉底。建议在 ROADMAP 增一节"调研采纳待办"（链接调研文档 + 验收 commit），并把已采纳项按每轮消化 1–2 个排期；文档漂移检查可加一条"调研文档结论 vs YAMET.md 提及"。
6. **【P3】PraisonAI S3（goal judge fail-open + tail-only）**：graph 已支持 judge 节点，补上"只取 goal+尾部、异常放行"的判据能显著减少大图上的 judge token 消耗——等 graph 使用量上来再做。
