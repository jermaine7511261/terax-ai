## 0. 本轮定位（用户命题）

用户以「对照业界 AI 原生终端（Warp / Ghostty / Zed / VSCode）还能做什么原生」命题审视 yamet，结论：

**协议类能力（PTY / LSP / DAP / MCP）已 100% Rust 原生**（原生铁律已落实，见 `YAMET.md:32`）。但存在若干**滚动缓冲 / 搜索索引 / 会话恢复**能力仍停留在**前端内存 / 每次全扫 / 前端 store 落盘**层面，是「AI 原生终端差异化点」的缺口。

本轮把三类候选（全部 P1）**做成真能用的原生实现**，同时明确**被原生铁律禁止**的（tmux、Node/Python 桥接、VSCode 扩展宿主）不做。

> 维护者已确认取消 Markdown 渲染下沉（仅静态预览价值低）与剪贴板系统镜像（已有 `tauri-plugin-clipboard-manager`，OSC 52 场景接 plugin 改动小价值低）两个候选，本轮聚焦下列三项。

### 候选分级
| 候选 | 现状证据 | 目标原生度 |
|---|---|---|
| **P1 · 终端滚动缓冲区下沉** | `rendererPool.ts:211` `SerializeAddon`（前端序列化）；滚动缓冲存 xterm 内存 | Rust 侧维护会话滚动缓冲快照，大输出分页查询，前端零拷贝取页 |
| **P1 · 文件搜索增量索引** | `fs/search.rs:31` `MAX_SCANNED 50_000`（每次全扫无索引） | Rust mtime 增量缓存（监听 watch 事件增量更新），大仓库重复搜索秒级 |
| **P1 · 会话原子持久化** | `spaces/lib/useSpacePersistence.ts`（前端 store 落盘，非原子）| Rust 侧原子写快照（`.tmp` + rename），崩溃不丢工作区 |

**验收**：三文件同步项落地；`pnpm check-drift` 绿。

### P1 · 终端滚动缓冲区下沉 Rust（T1/T2）
1. **Rust 侧会话滚动缓冲**：`pty_helper` 或 `pty` 模块持有会话滚动缓冲快照（环形，如 10k 行）。
   - **方案 A**：仅提供 `pty_buffer_snapshot(session_id) -> lines[]` 命令，前端按需分页拉取（当前不连续缓冲，前端仍主渲染）。
   - **方案 B**：Rust 持续镜像缓冲，前端滚动时按窗口懒加载（大输出分页，前端不持全量）。**（推荐）**
   - **方案 C**：完整双缓冲（Rust 权威 + 前端镜像），工作量大。
2. **命令**：`pty_buffer_lines(session_id, start, count)` 分页查询。
3. **崩溃恢复**：helper 崩溃后新 helper 可经缓冲命令恢复滚动内容（配合既有 attach）。

**验收**：`pty_buffer_lines` 单测；大输出（>1MB log）滚动流畅不卡 UI；关闭标签重开后缓冲可恢复；`cargo test pty` 绿。

### P1 · 文件搜索增量索引（S1/S2）
1. **Rust 搜索索引**：复用 `fs/watch.rs` 的 `notify` 事件源，为工作区建增量缓存。
   - **方案 A**：目录级 mtime 缓存——`fs_search` 跳过未变更目录（伪索引，轻量）。**（推荐，先做可行子集）**
   - **方案 B**：完整 ripgrep 增量索引（watch 事件 → 更新文件清单 → 搜索命中缓存）。
   - **方案 C**：仅提升 `MAX_SCANNED`（治标）。
2. **命令**：`fs_search` 内部接索引；索引失效/缺失时回退全扫。
3. **范围**：只索引文本文件 + 遵守 `.gitignore`/`PRUNE_DIRS`。

**验收**：重复搜索同仓库，第二次命中缓存（可测 timing 或索引计数）；大仓库搜索不超时；`cargo test fs_search` 绿。

### P1 · 会话原子持久化（C1/C2）
1. **Rust 侧原子快照**：新增 `spaces_save(snapshot)` / `spaces_load()` 命令，`.tmp` + rename 原子写。
   - **方案 A**：前端序列化 → Rust 原子写盘（替代 `useSpacePersistence` 的直写）。**（推荐，改动最小）**
   - **方案 B**：序列化也下沉 Rust（结构化 snapshot 类型）。
2. **崩溃恢复**：启动时检测 `.tmp` 残留 → 用完整快照恢复；损坏快照回退最近完好版。

**验收**：`spaces_save/load` 单测（原子性、损坏回退）；崩溃模拟不丢工作区；`cargo test spaces` 绿。

## 4. 规划方案（技术设计）

### 4.1 滚动缓冲（方案 B）
- `pty` 模块加 `Arc<Mutex<RingBuffer<String>>>` 每会话；`write` 时镜像入缓冲。
- `pty_buffer_lines(session_id, start, count)` 命令从 RingBuffer 取。
- 前端 `rendererPool` 大输出时经该命令分页。
- 接缝：`pty_helper/server.rs` 的 `output()` 回调里 push 入缓冲；helper 崩溃后经 `attach` 重新挂载缓冲。

### 4.2 搜索索引（方案 A）
- `fs/watch.rs` 事件 → 更新 `HashMap<dir, mtime_cache>`；`fs_search` 先查缓存跳过未变更目录。
- 索引存内存（`Mutex<HashMap<PathBuf, u64>>`），随 watch 事件增量更新；缺失时回退全扫。

### 4.3 原子快照（方案 A）
- `spaces_save(snapshot)`：写 `snapshot.tmp` → `fs::rename` 为 `snapshot.json`（原子）。
- `spaces_load()`：读 `snapshot.json`；若 `.tmp` 残留说明上次写未完成 → 用旧版 + 清理 `.tmp`。
- 命令壳 + `pub fn *_impl` 纯函数（可测）。
