# 第三十一轮迭代需求：主窗口左下角文件夹选项卡 → 工作区选择器（深度调研）

> 命题：把主窗口左下角的文件夹选项卡（文件树面板头部 / 侧栏文件图标）设计成"选择工作区"入口，深度调研可行方案。
> 调研方式：源码级现状盘点（递归 grep + 文件通读）+ 本地 27 项目实证（opencode-dev 最近项目实现）+ 业界既有知识对照。web 深调研受沙箱限制（DNS 私有解析拦截 web_search/fetch_url，本轮实测仍拦截），业界部分以既有知识如实标注、不编造来源。
> 输出：本调研文档（现状 + 缺口 + 三档方案 + 推荐落地清单）。

## §0 现状盘点（源码实证）

### 0.1 "左下角文件夹选项卡"是什么

主窗口左下角与"文件夹"相关的 UI 有两处：

| 位置 | 组件 | 当前行为 |
|---|---|---|
| 左侧栏底部图标条 | `src/modules/sidebar/SidebarRail.tsx`（36px 横向 rail） | 第一个按钮 `explorer`（FolderTreeIcon + `sidebar.files`），点击仅切换 `sidebarView` 到文件树面板 |
| 文件树面板头部 | `src/modules/explorer/FileExplorer.tsx`（h-8 条，`basename(rootPath)` + 搜索/新建文件/新建文件夹/刷新按钮） | 头部标题**只读展示**，不可点，无任何切换入口 |

### 0.2 现有工作区机制（能力已齐、入口分散）

| 能力 | 位置 | 说明 |
|---|---|---|
| 打开文件夹（系统对话框） | `useWorkspaceSwitcher.openFolder()`（`src/app/hooks/useWorkspaceSwitcher.ts:188`） | openDialog → dirty 检查 → clearWorkspaceState → authorizeHome → resetWorkspace；已接命令面板 `workspace.openFolder` |
| local⇄WSL 环境切换 | `switchWorkspace(env)`（同文件 :131）+ 状态栏 `WorkspaceEnvSelector`（`src/modules/statusbar/WorkspaceEnvSelector.tsx`） | 状态栏显示 "Windows"/"WSL: xxx"，下拉列出 `wsl_list_distros`；切换后联动 `space.setEnv + pushRecent`（App.tsx:262 `handleWorkspaceChange`） |
| 工作区根持久化 | `settings/store.ts` `KEY_WORKSPACE_ROOT`（:308）单值 localStorage | 设置页 GeneralSection 可改，文案仍写"重启后生效"（实际 `useWorkspaceSwitcher` 的 `onPreferencesChange` 已让其在会话内生效——**文案过时**） |

### 0.3 关键发现（决定方案语义）

1. **文件树头部显示的不是工作区根**：`useWorkspaceCwd`（`src/modules/tabs/lib/useWorkspaceCwd.ts`）的 `explorerRoot` **终端优先**（活动终端 cwd → 最近终端 cwd → home）。即左下角文件夹选项卡当前展示的是"终端所在目录"，与全局工作区（home/launchCwd + env）是**两个不同概念**。方案必须明确：选择器管理的是**全局工作区**，文件树面板跟随终端 cwd 的现状保持不变（这是特性：终端 cd 到哪、文件树看到哪）。
2. **无「最近工作区」历史**：全仓库 grep `recentWorkspace/recentFolders/recentProjects` 零结果。最近列表的**现成参照模式**已存在：`modelPrefs.ts pushRecentModel`（去重置顶 + RECENTS_MAX=5 截断）、spaces store `recentWith`。
3. **openFolder 与 switchWorkspace 是两条独立路径**：前者切任意目录（本地）、后者只切 env（home 取 env 默认）。"选择最近工作区"需要把两者组合成统一入口。

## §2 可行方案

### 方案 A：轻量接线（0.5d，立即可做）

- `FileExplorer` 头部标题条改为按钮（folder 图标 + basename + chevron），点击调 `openFolder()`（复用命令面板 `workspace.openFolder` 的现成逻辑，需要把该函数从 App 层下传为 prop）。
- `SidebarRail` explorer 按钮不变。

**优点**：改动最小、零新状态、全复用。**缺点**：无最近列表、无 WSL 集成、无键盘导航，发现性一般。**适用**：只是想让"点文件夹能换工作区"的最小兑现。

### 方案 B：WorkspaceSwitcher 弹层（推荐，2–3d）

新增 `src/modules/workspace/WorkspaceSwitcher.tsx`（Popover/Dialog，复用 SpaceSwitcher 的交互范式：键盘 ↑↓/Enter/Esc、模糊过滤），三段式：

1. **当前工作区**：名称（basename）+ 完整路径 + env 徽标（Windows / WSL:xxx），右上"打开其他文件夹…"（openDialog）。
2. **最近工作区**：新持久化 `recentWorkspaces`（localStorage JSON 数组，`{ path, env, lastOpenedAt }`，上限 8，去重置顶——完全复制 `modelPrefs.ts pushRecentModel` 模式 + 存在性校验：目录已删除则标灰可清除）。行内显示相对时间、支持删除。
3. **WSL 快捷区**：`wsl_list_distros` 列表（含 running 徽标），选中 = env 切换。

**触发点（3 处，全部指向同一弹层）**：
- FileExplorer 头部标题条（改成可点按钮 + chevron）；
- SidebarRail explorer 按钮：首次点击切视图，**再次点击**（active 时）打开切换器；
- 命令面板 `workspace.openFolder` 升级为 `workspace.switch`（保留原命令别名）。

**行为与联动**（复用 `useWorkspaceSwitcher` 并抽公共函数）：
- 抽 `adoptFolder(path)`：dirty 检查 → clearWorkspaceState → `workspaceSetCurrent` → `setWorkspaceRoot`（持久化）→ `workspaceAuthorize` → resetWorkspace → **pushRecentWorkspace** → 同步 active space（`setRoot + setEnv + pushRecent`，沿用 `handleWorkspaceChange` 模式）。
- 最近项 env 与当前不同 → 先 `switchWorkspace(env)` 再 `adoptFolder(path)`（注意 switchWorkspace 内部 home 解析只认 env 默认 home，路径需二次 adopt）。
- 空态：首次使用无最近项时，弹层直接聚焦"打开其他文件夹…"。

**持久化与测试**：`settings/store.ts` 新增 `KEY_RECENT_WORKSPACES`；纯函数 `pushRecentWorkspace / removeRecentWorkspace`（参照 `modelPrefs.ts`）→ 单测（去重/上限/删除/空）；组件测试参照 SpaceSwitcher 测试（键盘导航、选中回调、空态）。

**i18n**：`workspaceSwitcher.*` 双语 key（当前工作区/最近工作区/打开其他文件夹/WSL 发行版/移出最近列表）；顺带修正 `settingsGeneral.workspaceRootHint` 的"重启后生效"过时文案。

**预算约束**：主窗口 eager 预算锁死（`eager-budget.test.ts`），WorkspaceSwitcher 仅 React + hugeicons + 现有 UI 原语，不引 CodeMirror/ai-sdk，风险低；若引用 dialog 类重组件则走 `React.lazy`。

### 方案 C：启动页式项目选择（远期，1w+）

opencode-dev home 式：首屏/新窗口显示最近项目卡片网格 + 打开/新建/克隆（git clone 输入框）。与"左下角文件夹选项卡"的诉求偏离（那是常驻入口，不是首屏），**不建议本轮做**，可列入 ROADMAP 更远期。
