# Yamet 国内 IM 平台接入方案与迭代实施规划

> 规划日期：2026-08-03
> 范围限定：仅接入国内平台 —— QQ、微信、企业微信、飞书、钉钉
> 依据：[IM 与网关调研总结](./yamet-IM网关调研总结-2026-08-03.md) / [迭代实施规划](./yamet-IM网关迭代实施规划-2026-08-03.md)
> 参考实现：LangBot（aiocqhttp/qqofficial/lark/dingtalk/wecom/openclaw_weixin）、hermes（feishu/wecom/dingtalk/qqbot/weixin）

> **实现状态（更新）**：本方案所列 6 平台（钉钉、飞书、企业微信、QQ、微信个人、微信公众号）已在 `src-tauri/src/modules/gateway/` **全部实现并接入**，含默认拒绝 + 会话审批白名单的认证门禁与 OS keychain 凭据持久化。微信个人经 iLink 扫码登录（`gateway_weixin_qr_login` 在设置页展示二维码），QQ 走 OneBot v11/go-cqhttp。本文保留为协议调研与接入依据；以 `YAMET.md` 的 gateway 子系统描述为准。

---

## 0. 一句话结论

**最优迭代顺序：钉钉 → 飞书 → 企业微信 → QQ → 微信（个人）→ 微信公众号**。理由：钉钉的 Stream 模式**主动外连、完全免公网端口**，最契合我们已规划的 relay 架构，可用最少投入验证全链路；飞书、企业微信官方 API 成熟稳定；QQ 走 OneBot/官方有门槛；**微信个人经腾讯 iLink Bot API + 手机扫码登录接入（官方接口，非 hook 封号方案），可做**；微信公众号为官方合规的 B 端/订阅补充。

|---|---|---|---|---|---|---|
| **钉钉** | `dingtalk-stream`（官方 Stream 长连接，**网关主动外连**）| ❌ 免公网 | ✅ 官方 | LangBot `dingtalk.py`、hermes `dingtalk/` | 中 | 官方，稳定 |

## 2. 最优迭代顺序（含理由）

### 为什么钉钉先做
- **Stream 模式 = 网关主动外连**：钉钉官方 `dingtalk-stream` 是客户端（我们的网关）主动连钉钉的长连接，**无需任何公网入站端口**。这与我们 P2 的 relay/外连架构**完全同构**，可用它一次性验证「认证 → 消息归一化 → 会话 → 派发 agent → 回发」全链路，而不用先解决公网穿透。
- 官方支持、文档齐全、LangBot/hermes 有现成实现可对照。
- 国内 B 端办公高频，价值高。

### 整体顺序
| 阶段 | 平台 | 主要工作 | 复用/验证 |
|---|---|---|---|
| **S1** | 网关核心 | `PlatformAdapter` trait + `MessageEvent` + 会话 key + 认证 | 全平台地基（P1）|
| **S2** | **钉钉** | Stream 长连接适配器（主动外连，免公网）| 验证全链路 + relay 同构 |
| **S3** | **飞书** | lark 事件订阅适配器（先长连接模式免公网）| 复用 S1/S2 |
| **S4** | **企业微信** | 官方 API 回调适配器（自建应用）| 复用 S1/S2 |
| **S5** | **QQ** | OneBot 协议（go-cqhttp 本地中转）适配器 | 复用 S1/S2 |
| **S6** | **微信（个人）** | 腾讯 iLink Bot API + 扫码登录适配器（长轮询 + context_token 回声 + AES CDN 媒体）| 复用 S1/S2 |
| **S7** | **微信公众号** | 官方开放平台回调 | 官方合规 |

## 3. 分阶段实施规划

### S1 — 网关核心（Rust crate `modules/gateway/`）
复用通用规划的 P1。要点：
- **参考**：hermes `gateway/platforms/base.py`（`BasePlatformAdapter` 接口 + `MessageEvent` + 两级守卫 + 消息截断/平台长度上限 UTF-16）、`gateway/session.py`（会话 key + SQLite + PII 脱敏）、`gateway/turn_lease.py`（轮次租约）、`gateway/relay/auth.py`（HMAC 双签名 + 密钥轮换）、`gateway/platform_registry.py`（注册表 + 延迟加载）。
- `trait PlatformAdapter { connect/disconnect/send_message/run }` + `MessageEvent` 统一模型 + `build_session_key`。
- 会话 key 编码路由：`agent:main:{platform}:{chat_type}:{chat_id}`（国内平台 chat_id 语义各异：钉钉 conversationId、飞书 open_chat_id、企微 touser、QQ group/user、公众号 openid）。
- 认证前置 + 白名单 + 配对码 + 默认拒绝。
- **验收**：本地 Tauri IPC 适配器端到端跑通一条消息。

### S2 — 钉钉（首个平台）
- **参考**：hermes `plugins/platforms/dingtalk/adapter.py`（适配器结构、消息归一化到 `MessageEvent`）；LangBot `dingtalk.py` + `libs/dingtalk_api`（`DingTalkClient`、`DingTalkEvent` 事件模型、markdown/卡片消息转换）。
- 接入：`dingtalk-stream` 协议（WebSocket 长连接，主动外连）。
- 接收：机器人事件（单聊/群聊）→ 归一化 `MessageEvent`。
- 发送：钉钉机器人消息（text/markdown/卡片，主动 `send` + 回复）。
- 认证：AppKey/AppSecret（存 OS keychain）。
- **验收**：真实钉钉机器人单聊 + 群聊收发，驱动 agent 执行；断线自动重连。

### S3 — 飞书
- **参考**：hermes `plugins/platforms/feishu/adapter.py`（事件订阅 + 消息归一化 + `feishu_comment.py` 评论回复 + `feishu_meeting_invite.py`）；LangBot `lark.py`（lark 事件订阅 + `im.message.receive_v1` + 主动发送）。
- 接入：`lark-oapi` 风格，先走**长连接事件订阅**（免公网），Webhook 作可选项。
- 接收：`im.message.receive_v1` 等事件 → `MessageEvent`。
- 发送：机器人消息 API（text/post/interactive）。
- 认证：App ID/Secret，事件校验（`timestamp + nonce + 加密`）。
- **验收**：飞书机器人单聊/群聊收发。

### S4 — 企业微信
- **参考**：hermes `plugins/platforms/wecom/`（`adapter.py` + `callback_adapter.py` 回调接收 + `wecom_crypto.py` AES-CBC 加解密/签名验签）；LangBot `wecom.py` + `libs/wecom_api`（官方 API 封装、应用消息）。
- 接入：官方 API，自建应用接收消息回调（需公网接收，或企业微信「回调地址」；若不可用公网则评估替代）。
- 接收：`TextMsg` 等 → `MessageEvent`。
- 发送：`send` 应用消息到 user/chat。
- 认证：CorpID + Secret + 回调 token/encodingAESKey（解密）。
- **验收**：企微应用收发消息。

### S5 — QQ
- **参考**：LangBot `aiocqhttp.py`（OneBot/aiocqhttp 连接、消息段转换、CQ 码）；hermes `gateway/platforms/qqbot/`（`adapter.py` + `crypto.py` + `keyboards.py` + `chunked_upload.py` 分片上传 + `onboard.py` 配置）。
- 接入：OneBot 协议（`aiocqhttp` 兼容），go-cqhttp 作为本地中转（WS 连接本地 `ws://127.0.0.1`）。
- 接收：`message` 事件 → `MessageEvent`（区分私聊/群聊）。
- 发送：`send_private_msg`/`send_group_msg`。
- 认证：go-cqhttp 的 access token（本地）。
- **验收**：OneBot 本地连接，QQ 私聊/群聊收发。（或评估 QQ 官方机器人 API。）

### S6 — 微信（个人，腾讯 iLink Bot API）
- **参考（唯一权威，逐行照搬）**：hermes `gateway/platforms/weixin.py` —— iLink 端点（`getupdates/sendmessage/sendtyping/getconfig/get_bot_qrcode/get_qrcode_status`）、扫码登录、长轮询 35s、`context_token` 回声、AES-128-ECB CDN 媒体、会话过期（errcode -14）重扫、频率限制（-2）退避、`save_weixin_account` 凭据持久化（0600）。
- 接入：`ilinkai.weixin.qq.com` 的 iLink Bot API（HTTP + 长轮询，非 hook）。
- 扫码登录：`get_bot_qrcode` 取二维码 → 用户手机微信扫码 → `get_qrcode_status` 轮询确认 → 保存 token（`save_weixin_account`，`chmod 0600`）。
- 接收：`getupdates` 长轮询（35s 超时）驱动入站 → 归一化 `MessageEvent`（区分 dm/group，`_guess_chat_type`）。
- 发送：`sendmessage`，**必须回声最新 `context_token`**；支持 typing（`sendtyping`，ticket 从 `getconfig` 缓存）。
- 媒体：AES-128-ECB 加密 CDN 上传/下载（`encrypted_query_param`）。
- 会话保活：`errcode -14`（session expired）→ 重新扫码；频率限制 `-2` + 指数退避。
- 认证：Bearer token（存 OS keychain）。
- **验收**：微信个人扫码登录，单聊/群聊收发消息并驱动 agent；断线重连 + 会话过期重扫。

### S7 — 微信公众号
- **参考**：LangBot `officialaccount.py`（官方开放平台回调、AES-CBC 加解密、被动/客服消息）；hermes 的 webhook 接收模式（`gateway/platforms/msgraph_webhook` / `webhook` 的验签 + 归一化）。
- 接入：官方开放平台，消息回调（需公网）。
- 接收：`TextMsg` → `MessageEvent`。
- 发送：客服消息/模板。
- 认证：AppID/Secret + 校验 token。
- **验收**：公众号被动/客服消息收发。

## 4. 关键技术选型（Rust）

| 能力 | 选型 |
|---|---|
| 平台 WebSocket 长连接（钉钉/飞书/OneBot） | `tokio-tungstenite` |
| 主动外连 relay（同钉钉 Stream 同构） | 复用 P2 的 `RelayTransport` |
| 出站 HTTPS（企微/飞书/公众号 REST） | `reqwest`（复用 `net.rs` SSRF 防护）|
| 回调解密（企微/公众号 AES-CBC） | `aes` + `cbc` crate |
| HMAC/签名校验（回调 + stream 认证） | `hmac` + `sha2` |
| 会话持久化 | `rusqlite`/`sqlx` |
| 密钥存储 | OS keychain（复用 `secrets.rs`）|

**统一抽象**：5 个平台都实现同一个 `PlatformAdapter` trait，共用同一套 `MessageEvent` / 会话 / 投递 / 认证核心。每个平台是独立 feature（延迟加载），不拖慢启动、不增大 bundle（呼应 eager-budget）。

## 5. 风险与合规

- **微信个人**：经腾讯 iLink Bot API 接入（扫码登录，非 hook 封号方案）。受腾讯接口约束：需扫码授权、会话可能过期（errcode -14）需**重新扫码/保活**；`context_token` 必须回声；媒体走 AES-128-ECB 加密 CDN。参考 hermes `weixin.py` 的会话过期处理与扫码流程。
- **QQ**：个人 QQ 无官方 API，OneBot(go-cqhttp) 属灰色地带有账号风险；官方机器人需企业/资质审批。默认走 OneBot 本地，生产级评估官方。
- **公网需求**：优先选免公网平台/模式（钉钉 Stream、飞书长连接），减少 NAT/防火墙配置。
- **安全**：所有入站默认拒绝、认证前置；密钥存 keychain 绝不落盘；回调解密/签名校验在归一化边界完成。
- **平台风控**：批量/异常行为可能触发平台限流，需在投递层做速率控制（仿 hermes 消息长度上限 + 频率限制）。
