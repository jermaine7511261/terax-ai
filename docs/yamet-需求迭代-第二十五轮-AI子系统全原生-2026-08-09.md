### 0.2 核心结论（先讲清楚再设计）

1. **YaMet 已有九大系统的前端实现**（memory/skill/graph/multi-agent/loop/compact 等，见 §1），问题在「在 JS 层 = 非原生」。原生铁律要求 harness 类宿主进 Rust。
2. **grok-build 是 YaMet 原生化最直接蓝本**：Rust session 引擎 + 宿主原语 + Rust memory/skills/prompt/compaction，全部已落地且经 xAI 生产验证；thClaws/flock 提供「Rust 内核 + Tauri 前端」的分层示范。
3. **计算机使用（computer use）是唯一完全空白**：terminator/computer-agent/computer-use-linux 提供三平台原生参考；grok 无 computer use（其 Computer Hub 是工具路由非桌面控制），需自建。
4. **分期原则**：先「无外部副作用」的纯引擎（loop/context/prompt/harness），再「有状态持久化」（memory/skill/graph journal），最后「有系统权限」（computer use）。每期对齐前端已有的测试契约。

**下沉边界（保留前端的原则）**：
- **保留前端**：UI（AiChatPanel/ActivityStrip/GraphRunPanel/TodoStrip）、composer、附件、语音、审批卡片渲染、设置。
- **下沉 Rust**：LLM 调用（`ai_http_stream` 已可承载，复用 SSRF 代理 + Channel 流式）、turn 状态机、上下文选择/压缩、记忆存取、技能解析、子 agent 会话、graph 引擎、工具执行宿主、computer use 平台代码。
- **新增纯函数进 leaf 模块**（对齐「函数式核心」铁律）：turn 判定、cut 点、budget、schema 校验、junk 过滤等全部 Rust 纯函数 + 测试。

| **P1.5 网络** | **L2 web_search 下沉**（DDG 解析/uddg 还原/假成功检测/词汇级重排/类型化错误 + 多 provider 抽象）+ **L1 web_fetch 增强**（secret-in-URL 拦截 + 抓取清洗） | P0 | crw / search-cli / webclaw / hermes | 修 P0-1/P0-2/P1-1 缺陷；DDG 反爬漂移需持续跟踪 |
| **P2 状态** | memory（sqlite-vec/FTS5 三层）+ graph（engine+journal+approval）+ multi-agent（子会话+capability+output_schema） | P1 | grok memory/graph/subagent | 记忆/图/多 agent 测试契约量大 |
| **P3 权限** | **L3 deep_search 下沉**（research harness：researcher 工具面补 web 工具 + 并行 + exact-ID + plan→poll 预算，联动 P2 graph）+ computer use（M1→M3）+ 视觉回环 | P2 + P1.5 | grok deep_research / fetchira / terminator | 平台权限门槛高；Wayland 注入受限 |
| **P4 收尾** | 前端薄壳化（TS 层删冗余核心，仅留 UI）+ 双轨切换开关 + 性能/内存基准 | P0-P3 | thClaws/flock | 大重构回归面 |

**关键决策点（需确认）**：
1. **LLM 调用是否迁 Rust**：P0 即把模型调用从 `@ai-sdk` 前端迁到 Rust（`ai_http_stream` 直连 OpenAI-compatible）。这是「全原生」的根基，但架构级改动大；备选是保留前端调用、仅把 harness 状态机放 Rust（混合，成本低但非全原生）。
2. **是否引入 Rhai 工作流**（grok 模式）：graph 脚本化用 Rhai 引擎 + Rust 宿主原语，还是维持 Rust 原生 DSL / 保留前端 graph 引擎。Rhai 引入新依赖但可复用 grok 的 deep_research 蓝本。
3. **记忆是否本地 embedding**：`sqlite-vec` 需要本地 embedding 模型（或 FTS-only 降级）。是否内置 embedding（如 `fastembed` Rust 绑定 / 走 `ai_http_stream` 远程 embedding）。
4. **computer use 首发平台**：Windows（terminator 蓝本，YaMet 主平台）先落地 M1-M2。
5. **L2 web_search 源策略**：P1.5 先做 DDG 下沉 + 重排（免 key，修现存缺陷）；是否同步引入 provider 抽象（trait + registry）为 key 化源（Exa/Brave/Parallel 经 MCP）预留，还是 DDG-only 起步、抽象延后。
6. **L1 secret-in-URL 拦截强度**：hermes 是「整体拒绝」；YaMet 现有 `validate_url` 只拦 userinfo+SSRF+白名单。是否对白名单域外的 query 密钥参数也整体拒绝（更严）还是仅告警。默认建议整体拒绝（对齐 Hermes）。

## §4 约束与风险

- **原生铁律**：harness/记忆/skill/graph 宿主层必须 Rust 原生；前端只留 UI。禁止外部常驻桥接（cua-driver 之类外部二进制不可用，须自建原生）。
- **性能预算**：Rust 引擎零 IPC 往返增量（事件流走 Channel）；前端两条预算硬约束（eager-budget、懒加载）继续有效——新增 Rust 模块不增加 JS bundle。
- **安全**：模型调用全程走 SSRF 代理 + 配额；密钥不出 Rust（keyring）；untrusted 注入标注 + defang；computer use 输入注入 needsApproval + 敏感区黑名单；**web 结果全部 `<untrusted_tool_result>` 标注**（hermes 语义）+ `web_fetch` secret-in-URL 四路拒绝 + redirect 每跳 SSRF 复检。
- **测试**：每期核心子系统一条锁定不变量的测试（对齐 YaMet.md 质量门槛）；现有前端测试契约迁移为 Rust 命令面测试；网络搜索层用真实 HTML 夹具（uddg/anomaly/追踪链接形态）锁死解析行为。
- **双轨切换**：`useNativeAi` 开关，P0-P1 期前端/原生并存，逐系统验证后切换，避免一次性大爆炸重构。
