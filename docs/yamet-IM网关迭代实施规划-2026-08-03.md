# Yamet IM 与网关迭代实施规划

> 规划日期：2026-08-03
> 依据：[IM 与网关架构调研总结](./yamet-IM网关调研总结-2026-08-03.md)
> 目标：为 yamet（Rust/Tauri 桌面 agent 应用）分阶段落地 IM 接入与网关能力，复用调研中提炼的 10 条借鉴点
> 原则：每阶段可独立交付、可验收；demo/空壳视为失败（全部真能用）；功能性构建才递增版本

> **实现状态（更新）**：网关核心 + 6 平台适配器 + 认证门禁 + keychain 持久化已全部落地（见 `YAMET.md` gateway 子系统）。QQ 扫码 UI、企微/公众号回调隧道指南（`docs/gateway-callback-tunnel-guide.md`）、go-cqhttp 配置助手均已实现。本文保留为阶段规划参考。

## 0. 产品目标与两条产品线

yamet 是 AI-native 终端桌面应用，本规划把「IM/网关」落地为两条可并行的产品线，**共用阶段 1-2 的网关核心**：

- **方向 A — 远程消息接入（IM）**：用户通过 Telegram / WhatsApp 等 IM 平台向 yamet 的 agent 发消息、操控本机工作区（hermes 模式）。
- **方向 B — 远程控制 / Agent 协议**：外部 client（网页 / 移动端 / IDE）通过 relay 外连或 ACP 连接本机 yamet agent，远程执行任务（claude-code / grok / xora 模式）。

两者共享：`PlatformAdapter` 抽象 + relay 外连 + 认证 + 会话管理 + 投递。**先建核心，再分别挂 IM 平台与 ACP 面。**

## 2. P0 — 现状盘点（复用既有资产）

**已完成/可复用（不重写）**：
- Rust 安全 AI HTTP 代理 `src-tauri/src/modules/net.rs`（SSRF 全套：header 黑名单、IP 分类、DNS-rebinding 钉 IP、私网 opt-in、流式 `tauri::ipc::Channel`）→ 网关的出站 HTTP 基础。

- 外部 agent 启动器 + 钩子注入 `agent.rs`（OSC 777 生命周期标记）→ agent 状态观察基础。
- 进程内子代理 + 工具白名单 `agents/`。

**本阶段动作**：在 `docs/architecture/` 补一节「网关能力现状与缺口」；在 `src-tauri/src/modules/` 下新建 `gateway/` 模块骨架（纯空壳不算完成——需有第一个可用的本地适配器，见 P1）。

## 3. P1 — 网关核心抽象（Rust crate：`modules/gateway/`）

**借鉴**：hermes `BasePlatformAdapter` + 注册表 + `MessageEvent`；会话 key 编码。

**实施点**：

1. **`trait PlatformAdapter`**（`gateway/adapter.rs`）：
   ```rust
   #[async_trait]
   trait PlatformAdapter: Send + Sync {
       async fn connect(&mut self) -> Result<()>;
       async fn disconnect(&mut self);
       async fn send_message(&self, target: &Target, msg: &OutboundMessage) -> Result<SendReceipt>;
       async fn run(self, tx: Sender<MessageEvent>); // 归一化入站推给核心
   }
   ```
2. **统一消息模型** `MessageEvent { platform, chat_id, chat_type, user_id, thread_id, scope_id, profile, text, message_id }`，下游逻辑只看该模型。
3. **会话 key 工厂** `build_session_key(platform, chat_type, chat_id)`，格式 `agent:main:{platform}:{chat_type}:{chat_id}`，编码完整路由上下文（含 thread/profile），统一构造、拒绝路径穿越字符（`..` `/` 盘符）。
4. **注册表 + 延迟加载**：`AdapterRegistry` 按平台名注册工厂；重 SDK 依赖按 feature 门控，只在启用该平台时编译/加载。
5. **本地 Tauri IPC 适配器**（第一个真实现）：`LocalIpcAdapter` 实现同一 trait，入站来自 `invoke()` 的网关命令、出站经 `tauri::ipc::Channel` 回前端——**验证核心逻辑能端到端跑通**（消息进来 → 会话 key → 派发给 agent → 响应回发）。

**技术选型**：`async-trait`、`tokio`、`serde`。

**验收**：`cargo test` 覆盖「消息归一化 → 会话 key → 路由 → 回发」；本地 IPC 适配器在 UI 里能收发一条消息驱动 agent。

## 4. P2 — Relay 外连（无公网入站端口）

**借鉴**：hermes `gateway/relay/*`（HMAC 双签名、封顶指数退避、缓冲回放去重、4401 终态）。

**实施点**：
1. **`RelayTransport`**：app 作为 WS 客户端 dial 出 connector（`GATEWAY_RELAY_URL` 配置）。
2. **线协议**（换行分隔 JSON，与 hermes 字节级对齐）：
   - app→connector：`hello(type/platform/botId)`、`outbound(send/edit/typing)`、`interrupt`
   - connector→app：`descriptor(能力握手)`、`inbound(MessageEvent)`、`outbound_result(对应 requestId)`、`interrupt_inbound`
3. **认证（HMAC 双方案）**：
   - WS 升级：`Authorization: Bearer base64url(payload:exp:sig)`，`sig=HMAC_SHA256("gateway_id:exp", secret)`，TTL 300s；**多密钥列表**支持轮换。
   - 入站投递签名：`x-relay-timestamp` + `x-relay-signature`，`sig=HMAC_SHA256("ts.body_json", key)`，300s 重放窗口。
   - WS 关闭码 **4401** = 凭据撤销，视为终态不重连。
4. **断线重连**：`tokio-tungstenite` + 封顶指数退避（1s→30s）；区分「意外断开」（快速退避）与「主动休眠」（慢节奏 redial）；重连后按 `from_sequence_num` 续传 + 缓冲回放去重。

**技术选型**：`tokio-tungstenite`、`hmac`、`sha2`、`base64`、`serde_json`。

**验收**：本地起一个 mock connector（`examples/relay_connector.rs`），验证握手、双向消息、断线重连续传、签名校验、4401 终态。

## 5. P3 — 首个真实 IM 平台：Telegram

**借鉴**：hermes Telegram 适配器（python-telegram-bot 长轮询/webhook）。

**实施点**：
1. **`TelegramAdapter`** 实现 `PlatformAdapter`：
   - 长轮询 `getUpdates`（**无公网端口**，配 P2 的 relay 时经 relay 外连）+ 可选 webhook。
   - 入站归一化 `MessageEvent`；出站支持文本 / 流式 typing 指示 / 附件；遵守平台消息长度上限（UTF-16 4096）。
   - 密钥存 OS keychain（复用 `secrets.rs`，服务 `yamet-ai`），绝不落盘。
2. **授权**：DM 配对码（仿 hermes `pairing.py`：管理员 `/pair` 生成码，用户发码即授权）+ 白名单 + 默认拒绝；认证放在消息处理**最早**（agent/会话创建前）。
3. 前端设置页加「网关/IM」区：填 bot token、查看配对码、开关平台、测试连接（复用 `lm_ping` 同款探活）。

**验收**：真实 Telegram bot 端到端：用户发消息 → agent 收到并执行（读文件/跑命令）→ 结果回发；断线/重启后续传不丢消息。

## 6. P4 — ACP 对外暴露

**借鉴**：grok `xai-acp-lib/gateway.rs`（传输无关信道层）+ xora 三明治（渲染层 ⇄ ACP ⇄ 侧车）。

**实施点**：
1. **ACP 服务**：复用 `agent-client-protocol` crate，起一个 ACP server，把 yamet 进程内 agent 暴露给外部 client（`stdin`/NDJSON，或经 P2 relay）。
2. **信道解耦**：内部 `mpsc` 信道 + `oneshot` 关联请求/响应；协议语义（ACP 方法）与传输（stdio/WS/进程内）彻底分离。
3. **核心工程纪律**（直接抄 grok）：
   - 通知类消息（`session_notification`/`ext_notification`）**fire-and-forget**，不阻塞等 ACK。
   - 重连时 `same_channel` 判定**丢弃陈旧消息**、由 re-init 显式重建，不重放。
   - `AgentShutdownGuard`：所有退出路径都发 `Shutdown`（SessionEnd/memory save）。
4. **能力协商**：握手时协商 client capabilities，据此决定对 agent 开放的工具/权限/终端范围。
5. **PTY 独立通道**（可选）：终端 I/O 走独立 WS 流，与控制协议分离（仿 grok `ptyctl`）。

**验收**：一个外部 ACP client（示例 `examples/acp_client.rs`）能 newSession → prompt → 收工具调用 → 回结果 → closeSession；断线重连不重复执行。

## 7. P5 — 生产化

**借鉴**：hermes（会话/守卫/租约）+ jiuwenswarm（心跳/断连清理）。

**实施点**：
1. **会话持久化**：SQLite（`rusqlite`/`sqlx`）持久化会话 + 消息历史；会话 key 做路径穿越校验；用户/会话标识 PII 哈希脱敏。
2. **两级守卫**：适配器层（会话活跃 → 入队 `Mutex<VecDeque>` + `Notify` interrupt）+ 核心层（控制命令 `/stop /new /status /approve` 拦截内联派发）。**陈旧锁自愈**：owner task 退出后清理残留守卫。
3. **turn_lease 串行化**：每会话单租约，防止并发轮次互相覆盖。
4. **流式心跳**：空闲发 keepalive（专用 seq=-1）防连接被掐；`send_lock` 串行保帧序。
5. **断连统一清理**：`finally` 依次取消所有 in-flight → cancel agent 内部工作 → 停调度器 → 清理流，无孤儿任务（对应用关闭窗口/崩溃的兜底）。
6. **scale-to-zero（可选）**：网关空闲 → 通知 connector 切 buffered-only → 休眠；新入站唤醒重连。

**验收**：长时间运行稳定；模拟崩溃/断网后续传恢复；无孤儿进程/任务；消息不丢不重。

## 8. P6 — 远程控制面板（可选增强）

**借鉴**：claude-code-haha（长轮询/SSE 远程操控本地 CLI）。

**实施点**：基于 P2 relay 或 ACP，做一个轻量网页/移动端视图，远程查看本机 agent 会话、发起任务、审批工具调用（复用 yamet 现有 `AiToolApproval` 审批流）。

## 9. 风险与取舍

- **安全**：网关 = 攻击面扩大。所有入站默认拒绝、认证前置；HMAC 密钥轮换；私网访问 opt-in（复用 net.rs SSRF 防护思路）；工具审批流在远程上下文同样生效。
- **桌面优先取舍**：若主要面向本机 UI，可不做完整多平台；但保留 `PlatformAdapter` trait + relay，未来接移动/网页零重构。
- **依赖体积**：重 SDK 平台（discord.py/slack_bolt 类）用 feature 门控延迟加载，避免拖慢 yamet 启动与增大 bundle（呼应 eager-budget 约束）。

## 10. 建议实施顺序与版本节奏

1. **先做 P1**（核心抽象 + 本地 IPC 适配器跑通）—— 功能性构建，递增版本至 0.2.0。
2. **P2 relay**（无公网端口外连）—— 功能性构建，0.3.0。
3. **P3 Telegram**（首个真实 IM 平台）—— 功能性构建，0.4.0。
4. **P4 ACP**（外部 client 连接）—— 功能性构建，0.5.0。
5. **P5 生产化** —— 视稳定性，bug 修复不递增版本。
6. **P6 远程面板** —— 后续增强。

> 版本规则：仅功能性构建递增版本（四处同步 package.json/tauri.conf.json/Cargo.toml/Cargo.lock）；bug 修复不递增。
